# Community site API

Serverless-функции сайта сообщества. Сейчас одна: `/api/notes` держит заметки страницы [«Аукцион 2026»](../../docs/published/auction-2026/index.html). Языковые правила — `proj-write-typescript`. Команды — `just community-site-api-*`.

- `src/` — чистая логика документа: разбор недоверенного состояния, ревизии, версии, откаты. Ни Netlify, ни сети, ни `Date.now()`: момент приходит аргументом. Это единственное, что покрыто тестами, и единственное, что может ошибиться дорого.
- `netlify/functions/` — HTTP-граница: маршрут, коды ответа, Netlify Blobs. Решений не принимает.
- Сборки у компонента нет: функцию бандлит Netlify CLI при деплое сайта. Гейт — `typecheck`, `lint` и тесты.
- Конфигурация стека — `package.json`, `tsconfig.json`, `biome.json`, `vitest.config.ts`.

## Границы

- Авторизации нет по решению владельца. Пропуск к документу — его идентификатор: 128 случайных бит в ссылке. Идентификатор не логируется и не попадает в тексты ошибок.
- Blobs не умеют условной записи, поэтому чтение и запись внутри обработчика остаются гонкой. Её сужает `baseRevision`: запись поверх чужой отклоняется с `409` и актуальным документом в теле. Остаточное окно закрывают версии, из которых состояние восстанавливается.
- Продакшен пишет в глобальный store, превью и ветки — в store своего деплоя. Проверочный документ рядом с рабочим не лежит.
- Хранится состояние страницы, а не домен аукциона. Доменная модель аукциона в MVP не входит и будет проектироваться с нуля.

## Контракт

| Запрос | Действие |
|---|---|
| `POST /api/notes` | создать документ, тело `{ state? }` |
| `GET /api/notes/:docId` | прочитать документ целиком, вместе с версиями |
| `PUT /api/notes/:docId` | записать состояние, тело `{ baseRevision, state }` |
| `POST /api/notes/:docId/versions` | зафиксировать версию, тело `{ baseRevision, label? }` |
| `POST /api/notes/:docId/restore` | вернуть версию, тело `{ baseRevision, version }` |

Возврат версии ничего не удаляет: содержимое старой версии становится текущим состоянием и одновременно новой версией, поэтому ошибочный возврат отменяется тем же действием.

Заметки читаются снаружи обычным `GET` по адресу документа — отдельного экспорта для этого не нужно.
