# Community site API

Serverless-функции сайта сообщества. Сейчас одна: `/api/notes` держит заметки страницы [«Аукцион 2026»](../../docs/published/auction-2026/index.html). Языковые правила — `proj-write-typescript`. Команды — `just community-site-api-*`.

- `src/` — чистая логика документа: разбор недоверенного состояния, ревизии, версии, откаты. Ни Netlify, ни сети, ни `Date.now()`: момент приходит аргументом. Здесь ошибка стоит дороже всего: это единственное место, где теряются заметки.
- `netlify/functions/` — HTTP-граница: маршрут, коды ответа, Netlify Blobs. Решений не принимает.
- `page/` — тесты опубликованной страницы: её клиентская логика в jsdom и проверки разметки. Страница лежит в `docs/published/`, поэтому каталог тянется к ней через `../../`. Шов временный: он исчезнет, когда сайт станет одним компонентом.
- `e2e/` — сценарии в настоящем браузере и проверочный сервер под них: настоящая статика `docs/published` плюс настоящий обработчик, подменено только хранилище Blobs. Тот же сервер поднимает `just community-site-serve` для ручного прогона.
- Тесты лежат рядом с тем, что проверяют, и покрывают четыре слоя: логику документа (`src/document.test.ts`), границу функции с подменённым хранилищем (`netlify/functions/notes.test.mts`), страницу в jsdom (`page/`) и сценарии в браузере (`e2e/`).
- `npm test` и `npm run e2e` разделены намеренно: второму нужен скачанный Chromium, поэтому в `just verify` он не входит, а в CI идёт отдельными шагами.
- Сборки у компонента нет: функцию бандлит Netlify CLI при деплое сайта. Гейт — `typecheck`, `lint` и тесты.
- Конфигурация стека — `package.json`, `tsconfig.json`, `biome.json`, `vitest.config.ts`. `DOM` в `lib` нужен тестам страницы, а не функции.

## Границы

Хранилище, модель доступа, разрешение конкурентной записи и форма отката приняты [ADR-042](../../docs/decisions/ADR-042-published-page-notes-own-backend.md); там же их цена и сигналы пересмотра.

- Авторизации нет по решению владельца. Пропуск к документу — его идентификатор: 128 случайных бит в ссылке. Идентификатор не логируется и не попадает в тексты ошибок.
- Blobs не умеют условной записи, поэтому чтение и запись внутри обработчика остаются гонкой. Её сужает `baseRevision`: запись поверх чужой отклоняется с `409` и актуальным документом в теле. Остаточное окно закрывают версии, из которых состояние восстанавливается.
- Продакшен пишет в глобальный store, превью и ветки — в store своего деплоя. Проверочный документ рядом с рабочим не лежит.
- Хранится состояние страницы, а не домен аукциона. Доменная модель аукциона в MVP не входит и будет проектироваться с нуля.

## Контракт

| Запрос | Действие |
|---|---|
| `POST /api/notes` | создать документ, тело `{ state? }` |
| `GET /api/notes/:docId` | прочитать документ целиком, вместе с версиями |
| `PUT /api/notes/:docId` | записать состояние, тело `{ baseRevision, state }` |
| `POST /api/notes/:docId/versions` | зафиксировать версию, тело `{ baseRevision, label? }` |
| `POST /api/notes/:docId/restore` | вернуть версию, тело `{ baseRevision, version }` |

Возврат версии ничего не удаляет: содержимое старой версии становится текущим состоянием и одновременно новой версией, поэтому ошибочный возврат отменяется тем же действием.

Обещание «ничего не теряется» держит не только обработчик. Автосохранение пишет ревизии, а не версии, поэтому набранное после последней версии в истории не лежит — и страница фиксирует его версией «Состояние перед возвратом», прежде чем звать `/restore`. Решает это страница, а не обработчик: только она знает, что показано человеку, и только ей видно, было ли текущее состояние уже зафиксировано. Не удался снимок — возврат не выполняется вовсе.

Заметки читаются снаружи обычным `GET` по адресу документа — отдельного экспорта для этого не нужно.
