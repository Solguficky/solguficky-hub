# apps

Деплоимые компоненты платформы: backend-сервисы, боты и клиентские приложения.

Сейчас здесь только контур кодогенерации Identity: контракт режется в `gen/` при сборке, исполняемого сервиса ещё нет. Остальные MVP-компоненты появятся вместе с первым коммитом реализации. Намерение живёт в service briefs (`docs/services/`) и в Linear.

## Что попадает сюда

Компонент, который собирается, запускается и обслуживает продукт. Язык и тип клиента роли не играют: Meetups, Identity, новый Telegram Gateway и Telegram Mini App будут соседями по этому каталогу.

Подкаталог создаётся вместе с первым коммитом реализации, а не заранее.

## Граница с `legacy/`

`legacy/` хранит код предыдущего поколения. Компонент переезжает туда по явному решению владельца, когда выполнены все три условия:

- он исключён из CI и локальной оркестрации;
- он не деплоится и не обслуживает продукт;
- он сохраняется только до извлечения доменной модели, actor/event-логики, полезных тест-кейсов и непроверенных гипотез.

Обратного перехода нет. Из `legacy/` компонент не возвращается в `apps/`, а удаляется целиком после извлечения знаний; новая реализация того же домена начинается в `apps/` с нуля.

Временной слой и зрелость (Current / MVP / Future / Legacy) остаются в service briefs. Каталог фиксирует роль артефакта, а не его статус: статус меняется наблюдением, роль — только вашим решением.
