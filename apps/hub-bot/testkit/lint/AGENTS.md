# Линтер экрана

Линтер экрана и форма каталога экранов — исполнение правил [дизайн-кода](../../../../docs/design/bot/design-code.md#исполнение-правил) для обеих поверхностей пакета ботов и аукционного дерева. Языковые правила — `proj-write-typescript`. Команды — `just hub-bot-*`: линтер — тестовый код пакета ботов, и его тесты, typecheck и lint идут рецептами пакета.

- `catalog.ts` — форма записи каталога: класс сообщения, правило навигации — `root` у корневого меню, одного на каталог, `tree` с `[‹ Родитель]`, у разделов `[‹ Меню]`, `exit` у кадров исхода и подсказки, `apply` у приветствия: последний ряд ровно `[Подать заявку]`, без «‹» (PER-592), — заголовок, родитель, признак необратимого подтверждения `irreversible` — после «Да» обратного действия нет или тратятся деньги, и только его «Да» красится `danger` (решение владельца 10 октября 2026 года), — признак `pairedContent` у экрана, чьё содержимое стоит по два в ряд, — люди «Ставок зала» (PER-565), — `legacy` и именованные исключения `waive`. Сами каталоги держат поверхности рядом со своими экранами.
- `inspect.ts` — `inspectCall(config, method, payload)`: проверка вызова Bot API по каталогу и правилам, и накопитель найденного. Правило `body` читает только каркас текста — пустую строку после заголовка и пустоту над ним: исход — свой экран (PER-472), — а чем тело заполнено, держат тесты каталогов. Частное для поверхности — символ метки, каталог, родитель из нескольких экранов, именованные пары кнопок — приходит настройкой `LintConfig`, а не кодом линтера. В имени именованной пары `#` стоит на месте числа в подписи, например «📎 Материалы (#)|🧩 Расширения». Словарь у обеих поверхностей один и живёт здесь: голая подпись «Меню» вне его, в корень ведёт только возврат «‹ Меню»; словарь эмодзи (правило `emoji`) — модуль `src/core/pictograms.ts`, общий с экранами обоих ботов; там же разделы со знаком (`sectionLabels`, `sectionLines`), и голая подпись входа в раздел или строка «Аукцион:» без отступа без своего знака — нарушение `emoji` (PER-644). Поле записи `submenu` — подменю сходки: заголовок — название сходки, вторая строка — курсивом имя подменю, пустая строка — после неё.
- `graph.ts` — `inspectCatalog(config)`, правило `graph` (PER-592): граф дерева по записям каталога, а не по отправленным экранам — ровно один корень, у каждого экрана `tree` есть родитель (запись или группа `parentGroups` настройки), у родителя есть `backName` для «‹ …», цепочка родителей доходит до корня без обрыва и цикла. Так экран, который ни один тест не отрисовал, тоже не остаётся тупиком. Подтверждения, кадры исхода, кадры без доступа и приветствие в граф не входят. Поверхность зовёт её через `inspectCatalog(поверхность)` из `testkit/screen-lint.ts` в тесте своего каталога.
- `body.ts` — `inspectBody`: правила тела экрана до оболочки — `callback_data`, ширина ряда, число рядов. Его зовут тесты аукционного дерева.
- `index.ts` — вход линтера.

## Границы

- Прод-код линтер не импортирует: `tsconfig.build.json` пакета берёт только `src/` и `gen/`, и образ бота о линтере не знает.
- Зависимостей времени выполнения нет, и vitest линтер не импортирует: хук `afterEach`, снимающий найденное, лежит в `lint-setup.ts` test kit.
- Накопитель найденного — один модульный массив на процесс vitest: его делят обе поверхности, и снимает его `lint-setup.ts` после каждого теста.
- Правило, которое запись может снять исключением, — `WaivableRule`. Предел `callback_data`, цвет кнопки, словарь эмодзи, запретные слова розыгрыша (`forbidden-word`, инвариант 8 RFC-007, PER-500) и граф каталога (`graph`, PER-592) в него не входят. Причина исключения начинается с задачи: `PER-N: …`.
- L0 правил на настройке хаба — `testkit/screen-lint.test.ts`, свои тесты линтера лежат рядом с модулями.
