# Выбор языков и технологий

> **Статус:** Canonical для процесса выбора. Technology pool не является распределением будущих сервисов по языкам.

Язык назначается существующей задаче, а не наоборот.

## Матрица решения

Для сервиса сначала фиксируются:

- доменная сложность и инварианты;
- владение данными;
- consistency и concurrency;
- latency и throughput;
- интеграции и persistence;
- observability;
- зрелость библиотек;
- deployment footprint;
- скорость разработки владельца;
- учебная отдача именно на этом домене;
- стоимость ещё одного runtime в MVP.

Кандидаты сравниваются по одной шкале. Обязательные ограничения применяются до субъективного интереса к языку. Решение для конкретного сервиса фиксируется ADR после появления требований и последствий.

## Technology pool

| Технология | Текущая позиция |
|---|---|
| TypeScript + grammY | Accepted для нового Telegram Gateway; ADR pending |
| F#, C#, Kotlin, Go | Кандидаты для Meetups/Identity после требований |
| Scala + Apache Pekko | Future-направление для auction v2 |
| Kotlin | Интересен, но не закреплён за Content Feed |
| Go | Интересен, но не закреплён за Scheduler |
| Ruby | Интересен, но отдельная админка не обоснована |
| C# + Orleans | Future-гипотеза для Achievements |

Для списка интересов ADR не нужен. ADR нужен, когда реальный сервис, требования и последствия дают выбору архитектурный вес.

## Runtime-language budget MVP

Базовое ограничение:

- TypeScript на Telegram edge;
- один backend runtime по умолчанию;
- второй backend runtime допускается только при явном преимуществе, зафиксированном ADR.

Это не запрет полиглотности, а защита продуктового цикла от одновременного освоения нескольких operational stacks.

## Decision experiment для backend

После продуктовых сценариев выбирается один сквозной use case, например изменение сходки организатором с последующим чтением актуального состояния. Для 2–3 кандидатов сравниваются:

- доменная модель;
- API/contract boundary;
- persistence transaction;
- обработка ошибок;
- тестируемость;
- объём инфраструктурного glue;
- время реализации владельцем.

Эксперимент не должен превращаться в несколько production-ready прототипов. Его результат — достаточно свидетельств для решения и ADR.
