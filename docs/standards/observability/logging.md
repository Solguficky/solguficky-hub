# Standard: логирование и чувствительные данные

> **Статус:** Active  
> **Применимость:** все сервисы  
> **Связанные документы:** продуктовые privacy-принципы в `PROJECT_CONTEXT.md`

Логи должны помогать восстановить технический поток операции, не превращаясь в копию пользовательских данных Telegram.

## Правила

- Используй структурные поля вместо интерполяции значений в текст сообщения.
- Передавай correlation/operation identifier через границы, если он существует в команде или trace context.
- Логируй тип операции, subject, aggregate/service identifier, результат, длительность и категорию ошибки.
- Не логируй bot token, connection strings, пароли, секреты и полный configuration object.
- Не логируй произвольный текст Telegram-сообщения, callback payload или сформированное уведомление целиком. Допустимы длина, тип и технический идентификатор.
- Не используй `Information` для каждого шага внутри горячего цикла; подробности успешного выполнения относятся к `Debug`.
- Ожидаемый отказ входных данных — `Warning` или доменный результат, а не stack trace уровня `Error`.
- Не скрывай неожиданное исключение; логируй его один раз на boundary, где оно превращается в наблюдаемый отказ.

## Реализации

- C#-сервисы используют `ILogger`/Serilog и OpenTelemetry из ServiceDefaults там, где они подключены.
- Current Rust gateway использует `tracing` и JSON subscriber.
- Новые языковые реализации должны соблюдать семантику полей, но не обязаны копировать конкретную библиотеку.
