# Standard: логирование и чувствительные данные

> **Статус:** Active  
> **Применимость:** все сервисы  
> **Связанные документы:** [продуктовые privacy-принципы](../../product/overview.md#privacy-by-design-и-минимальные-привилегии)

Логи должны помогать восстановить технический поток операции, не превращаясь в копию пользовательских данных Telegram.

## Поля

Каркас записи одинаков во всех сервисах: по нему собирается один запрос, проходящий через всю цепочку сразу. Имена в `snake_case`.

Два слова ниже значат разное. **Граница** — место, где сервис принимает вызов и отвечает на него: транспортный интерцептор, обработчик update, консьюмер шины. Граница есть у каждого сервиса, и заполнение каркаса — её работа, а не работа вызываемого кода. **Край** — та единственная граница цепочки, на которую пришёл человек; в этом продукте это Telegram Bot. Только на краю рождаются значения, которые остальные сервисы уже не могут вычислить и лишь принимают готовыми.

| Поле | Тип | Кто заполняет | Обязательность |
|---|---|---|---|
| `service` | строка | автоматика границы | всегда |
| `use_case` | строка | разработчик на краю, дальше автоматика | всегда, кроме операции без сценария |
| `operation` | строка | автоматика границы | всегда |
| `result` | `ok` либо `error` | автоматика границы | всегда |
| `duration_us` | целое | автоматика границы | всегда |
| `request_id` | строка | автоматика края, дальше автоматика границы | всегда |
| `error_category` | строка | автоматика границы | при `result=error` |
| `error` | строка | автоматика границы | при `result=error` |
| `stack` | строка | автоматика границы | при неожиданном отказе |

- **`service`** — имя сервиса как константа его сборки, а не как метка сборщика логов. Метка контейнера в Loki выводится из имени контейнера и исчезает при переезде на log drains; значение внутри записи переживает смену транспорта доставки.
- **`use_case`** — имя продуктового сценария, а не транспортной операции. Один `use_case` покрывает цепочку целиком, от действия человека до ответа ему, и остаётся одинаковым во всех сервисах, которые в ней участвуют. Он рождается на краю, где сценарий начался, и проносится через границы тем же механизмом, что и `request_id`. Сервис в середине цепочки не выводит его из своего метода: разрешение личности обслуживает все сценарии сразу и о сценарии ничего не знает. Состав словаря — [PER-104](https://linear.app/anticnvm/issue/per-104).
- **`operation`** — транспортное имя операции: полное имя gRPC-метода, subject NATS, имя обработчика update. Оно отвечает на вопрос «какой код исполнялся», тогда как `use_case` — на вопрос «что делал человек». Одно значение `use_case` нормально собирает несколько разных `operation`.
- **`result`** — только `ok` либо `error`. Код транспорта в это поле не пишется: у него своё поле, названное по транспорту (`grpc_code` и аналоги). Иначе запрос «все отказы среза» приходится собирать перечислением трёх несовпадающих словарей, и добавление четвёртого транспорта ломает его молча.
- **`duration_us`** — микросекунды целым числом. Миллисекунды теряют разрешение на вызовах короче одной, а дробное значение тянет плавающую точку в JSON.
- **`request_id`** — сквозной идентификатор запроса, общий для всей цепочки. Механизм проноса — [PER-65](https://linear.app/anticnvm/issue/per-65).
- **`error_category`** — класс отказа, по которому он отличается от соседних без чтения текста. Состав значений — [PER-66](https://linear.app/anticnvm/issue/per-66).
- **`error`** — текст ошибки. Он подчиняется запретам ниже наравне с остальными полями: ошибка, в текст которой попал пользовательский ввод, санитизируется на границе, а не уезжает в лог как есть.

Операция без сценария — та, которую не начинал человек: health check, обработка сообщения шины по расписанию, периодическая фоновая работа. У неё `use_case` отсутствует, а не заполняется заглушкой.

Каркас описывает запись об операции. Запись о жизненном цикле процесса — старт, остановка, отказ конфигурации — операцией не является и несёт только `service` и свои поля: длительности и результата у неё нет.

Поля сверх каркаса сервис добавляет сам. Они подчиняются запретам ниже, и одно имя во всех сервисах значит одно и то же: запрос `| json | <поле>=…` не должен собирать записи с разной семантикой.

## Правила

- Используй структурные поля вместо интерполяции значений в текст сообщения.
- Заполняй каркас на каждой границе. Поле, которое нечем заполнить, опускается, а не пишется пустым: пустое значение неотличимо от заполненного при запросе на существование поля.
- Не логируй bot token, connection strings, пароли, секреты и полный configuration object.
- Не логируй произвольный текст Telegram-сообщения, callback payload или сформированное уведомление целиком. Допустимы длина, тип и технический идентификатор.
- Не пиши тело запроса и тело ответа ни на одном уровне, включая `Debug`. Флаг, включающий их в отладочной среде, не заводится: у продукта нет среды, в которой переписка человека становится отладочными данными.
- Не используй `Information` для каждого шага внутри горячего цикла; подробности успешного выполнения относятся к `Debug`.
- Ожидаемый отказ входных данных — `Warning` или доменный результат, а не stack trace уровня `Error`.
- Не скрывай неожиданное исключение; логируй его один раз на boundary, где оно превращается в наблюдаемый отказ.

## Кто не логирует

У записи об отказе ровно один автор. Отсюда следует, кто молчит:

- **Доменный слой** не логирует вовсе: он возвращает результат, а записать его решает граница.
- **Сгенерированный код** не логирует: его переписывает кодогенерация, и добавленная в него запись не переживёт следующую сборку.
- **Инфраструктурный адаптер** не логирует ожидаемый отказ, а возвращает его вызывающему. Записать и вернуть одну и ту же ошибку — значит получить её в логе столько раз, сколько слоёв она прошла.
- Неожиданный отказ записывает граница, на которой он стал наблюдаемым: транспортный интерцептор, обработчик update, консьюмер шины.

## Реализации

- C#-сервисы используют `ILogger`/Serilog и OpenTelemetry из ServiceDefaults там, где они подключены.
- Current Rust gateway использует `tracing` и JSON subscriber.
- Новые языковые реализации должны соблюдать семантику полей, но не обязаны копировать конкретную библиотеку.
