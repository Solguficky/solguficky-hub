# Standard: Ветвление и pull request

> **Статус:** Active  
> **Применимость:** ветки и pull request репозитория, включая работу агентов и подагентов  
> **Не применяется:** ветки, созданные внешними инструментами (`cursor/`, `codex/`, `claude/`) — их имя формирует чужой инструмент, и повлиять на него нельзя  
> **Связанные документы:** [commit-messages.md](commit-messages.md), [agent-execution-loop.md](../../development/agent-execution-loop.md)

Standard задаёт, от чего ветвится работа, как называются ветка и pull request и как результат возвращается в основную линию.

## Правила

### Ветки

- Модель ветвления — gitflow. `develop` — рабочая ветка и база всей разработки, `main` хранит состояние прода.
- Ветка задачи создаётся от актуального `develop`: `git switch -c feature/PER-84 develop`.
- Имя ветки — `feature/PER-N`: префикс, идентификатор Linear, ничего больше. Слаг названия в имя не входит, идентификатор пишется в верхнем регистре.
- Одна задача — одна ветка — один pull request. Вторая задача начинается новой веткой от `develop`, а не продолжением текущей.
- Агент работает только в `feature/PER-N`. `main` он не трогает: ни коммитом, ни мержем, ни переключением.
- Интеграционные ветки подагентов (`integration/<тема>`) создаются от `develop` по тем же правилам.

### Имя ветки создаёт скилл старта

Кнопка «Copy git branch name» в Linear и поле `gitBranchName` в его API отдают нижний регистр (`feature/per-84`); настройки регистра у интеграции нет — проверено 2026-08-28. Поэтому имя ветки собирает скилл старта из идентификатора задачи, а значение из Linear не используется.

Регистр в имени ветки Linear безразличен: связь ищется по идентификатору. Единый регистр нужен git, а не трекеру. Ветки, различающиеся только регистром, конфликтуют на уровне файловой системы на NTFS и APFS, поэтому регистр в репозитории один для всех веток.

### Pull request

- Заголовок PR — `[PER-N] Название задачи из Linear`. По нему Linear связывает работу с задачей и переводит её статус.
- Тело PR состоит из трёх частей: результат проверок, отклонения от утверждённого плана, находки ревью. Пересказ диффа в тело не входит — он читается в самом PR.
- PR из `feature/PER-N` вливается в `develop` через squash. PR из `develop` в `main` — через rebase.
- Ревью и мерж выполняет владелец. Агент открывает PR и останавливается.

## Проверка

- `git branch --show-current` возвращает `feature/PER-N` с идентификатором в верхнем регистре.
- `git merge-base --is-ancestor origin/develop HEAD` завершается успешно: ветка создана от актуального `develop` и не отстала от него.
- `git log --oneline origin/main..main` пуст: локальный `main` не получил ни одного коммита.
- Заголовок PR начинается с `[PER-N]`, а тело содержит все три части.
