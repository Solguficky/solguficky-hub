# Domain docs

Как скиллы читают доменную документацию этого репозитория перед работой с кодом.

## Перед исследованием прочитай

- **`docs/decisions/`** — ADR, затрагивающие область работы. Индекс — [README.md](../decisions/README.md). Файлы называются `ADR-NNN-<slug>.md`; каталога `docs/adr/` в репозитории нет.
- **Словарь домена Meetups и форма доменного события** — [ADR-031](../decisions/ADR-031-meetups-domain-vocabulary-and-event-form.md).
- **Бриф затронутого сервиса** в [services/](../services/README.md) — границы, данные и открытые вопросы компонента.

Отдельного `CONTEXT.md` в репозитории нет и он не заводится: словарь домена живёт в ADR, потому что термин здесь закрывается вместе с решением, а не отдельно от него. Скилл, ожидающий `CONTEXT.md`, читает вместо него ADR-031.

## Структура

Репозиторий single-context: `CONTEXT-MAP.md` нет и не будет, пока не появится несколько независимых доменных контекстов.

```
/
├── docs/decisions/       ← ADR-001 … ADR-032, включая словарь домена
├── docs/services/        ← брифы компонентов
└── apps/, shared/, contracts/
```

## Используй словарь домена

Называя доменное понятие — в заголовке задачи, гипотезе, имени теста — бери термин из ADR-031, а не синоним. Понятия нет в словаре — это сигнал: либо изобретается язык, которого в проекте нет, либо есть настоящий пробел. Пробел не закрывай сам: назови его владельцу.

## Сообщай о конфликте с ADR

Если вывод противоречит принятому ADR, скажи это явно, а не переопределяй молча:

> _Противоречит [ADR-024](../decisions/ADR-024-meetups-state-storage-with-domain-event-log.md), но стоит переоткрыть, потому что…_

Новый ADR оформляется только скиллом `proj-record-decision` и только после явного решения владельца. Если решение ещё не принято, место вопроса — RFC или обсуждение, а не ADR.
