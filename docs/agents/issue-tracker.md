# Issue tracker: Linear

Задачи, milestones и прогресс живут в Linear (workspace `anticnvm`). GitHub несёт только код и review: issues и PR там не планируются.

Структура бэклога, метки, оценки и жизненный цикл заданы нормативом [standards/backlog/linear.md](../standards/backlog/linear.md). Здесь только то, как до трекера дотянуться; правила норматива не пересказываются.

## Конвенции

- Инструмент — MCP-сервер Linear. Отдельного CLI нет. Если сервер не авторизован в сессии, скажи об этом прямо и не подменяй Linear на GitHub issues.
- **Завести или переписать задачу** — только через skill `sgh-create-task`.
- **Прочитать задачу** — `get_issue` по идентификатору вида `PER-20`; комментарии — `list_comments`.
- **Найти задачи** — `list_issues` с фильтром по проекту, статусу или метке.
- **Комментировать** — `save_comment`. **Статус, метки, оценка, `blockedBy`** — `save_issue`.
- **Ссылка из документа** — короткая форма URL без слага: `https://linear.app/anticnvm/issue/per-20`.

## Pull requests как поверхность запросов

**PRs as a request surface: no.** _(Поставь `yes`, если внешние PR на GitHub начнут поступать как запросы; флаг читает `/triage`.)_

## Когда skill говорит «опубликовать в issue tracker»

Заводи задачу в Linear через `sgh-create-task`.

## Когда skill говорит «взять соответствующий тикет»

Читай задачу через `get_issue` по идентификатору `PER-<N>`.

## Wayfinding

Используется `/wayfinder`. Карта — зонт с меткой `Epic` и префиксом `[Epic]` в названии, тикеты — его листья; третьего уровня вложенности нет. Блокировка — `blockedBy` и только там, где задача физически не стартует. Claim — назначение assignee. Резолюция — комментарий с ответом и закрытие задачи.
