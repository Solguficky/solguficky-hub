# Issue tracker: Linear

Задачи, milestones и прогресс живут в Linear (workspace `anticnvm`). GitHub несёт только код и review: issues и PR там не планируются.

Структура бэклога, метки, оценки и жизненный цикл заданы нормативом [standards/backlog/linear.md](../standards/backlog/linear.md). Здесь только то, как до трекера дотянуться; правила норматива не пересказываются. Файл входит в [контракт проекта для флоу](README.md).

## Идентификатор задачи

Вид `PER-N`, в верхнем регистре: `per-86` в аргументе команды означает `PER-86`. Ссылка из документа — короткая форма URL без слага: `https://linear.app/anticnvm/issue/per-20`; ссылка со слагом врёт после первого переименования задачи. Обратные ссылки на задачу ищутся командой `grep -rn "issue/per-<N>" docs/`.

## Конвенции

- Инструмент — MCP-сервер Linear. Отдельного CLI нет. Если сервер не авторизован в сессии, скажи об этом прямо и не подменяй Linear на GitHub issues.
- **Завести или переписать задачу** — только через skill `proj-create-task`.
- **Прочитать задачу** — `get_issue` по идентификатору вида `PER-20`; комментарии — `list_comments`. Пустое поле (`delegate`) в ответ не попадает: отсутствие поля читается как пустое значение, а не как непрочитанный сигнал.
- **Прочитать связи** — `get_issue` с `includeRelations: true`; без него граф выглядит пустым.
- **Найти задачи** — `list_issues` с фильтром по проекту, статусу или метке. Поиск дубликата захватывает входящие — статус Triage — и отменённые задачи.
- **Комментировать** — `save_comment`. **Статус, метки, оценка, `blockedBy`** — `save_issue`.

## Захват задачи

Что считается занятой задачей и когда ставится отметка, задаёт [контур исполнения](../development/agent-execution-loop.md#захват-задачи); здесь — чем читается каждый сигнал.

- `delegate` и статус — из ответа `get_issue`: поле `delegate` и `statusType`.
- Открытый pull request — `gh pr list --state open --search "PER-N"` и вложения задачи в том же ответе.
- Отметка захвата — `save_issue` с `state: started`. Дальше статус не двигается: его ведёт Linear по связанному pull request либо владелец.
- Отчёт и вопрос по задаче — `save_comment` на неё.

## Стоп-сигналы

Работа не начинается, пока решение не принято. Признаки в трекере: у задачи метка `Decision` или непустой `blockedBy`. Ставятся они по-разному: задача, внутри которой нужен выбор владельца, получает метку `Decision`; `blockedBy` — только там, где задача физически не стартует. Что делать, когда признак сработал, — раздел «Чекпоинты: план до кода» [контура исполнения](../development/agent-execution-loop.md#чекпоинты-план-до-кода).

## Особенности инструмента

MCP-сервер Linear портит данные молча в нескольких местах:

- `labels` в `save_issue` **заменяет весь набор**, а не дополняет. Сначала прочитай текущие метки через `get_issue`, потом передавай полный список.
- `blockedBy`, `blocks`, `relatedTo` только добавляют связи. Снимаются они через `removeBlocks`, `removeBlockedBy`, `removeRelatedTo`.
- `milestone` принимает имя или ID и **не принимает null**. Снять milestone из MCP нельзя — если задача должна уйти из активного milestone, скажи об этом пользователю явно.
- Операции архивации в MCP нет. Архивирует пользователь руками; ты только называешь кандидатов.
- Частичную правку описания делай через `patch`, а не перезаписью целиком.
- Сервер требует авторизации. Если её нет — остановись и скажи пользователю; коды и токены не запрашивай.

## Норматив

- Шаблон задачи, шкала оценок, таксономия меток, лимиты объёма, зависимости и жизненный цикл — [standards/backlog/linear.md](../standards/backlog/linear.md).
- Граница «работа или решение»: вопрос, ответ на который — выбор владельца, живёт в документе, а не в задаче. Таблица — [docs/README.md](../README.md).
- Новый milestone, зонт или проект не заводится без явной просьбы: состав и порядок утверждает владелец ([design-process.md](../development/design-process.md)).

## Когда skill говорит «опубликовать в issue tracker»

Заводи задачу в Linear через `proj-create-task`.

## Когда skill говорит «взять соответствующий тикет»

Читай задачу через `get_issue` по идентификатору `PER-<N>`.

## Чего здесь нет

Разбор Triage, декомпозиция milestone и планирование карты работ описаны нормативом и ведутся через `proj-create-task`. Внешние скиллы, приносящие собственный шаблон тикета или собственную иерархию, выключены в `.skillshare/skills/.skillignore` — причина в [agent-tooling.md](agent-tooling.md#внешние-скиллы).
