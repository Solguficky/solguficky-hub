# Observations: журнал в docs/development

Где лежит журнал наблюдений о процессе и куда уходит то, что наблюдением не является. Файл входит в [контракт проекта для флоу](README.md).

## Норматив

Форма записи, таблица адресатов, критерий независимого повторения и перевода в правило — [docs/development/observations.md](../development/observations.md). Стиль текста — [docs/STYLE.md](../STYLE.md).

## Как читать

`just observations` печатает все записи подряд, в порядке дат. Повторение распознаётся только по прочитанным записям, а не по ощущению «это уже было».

## Как записать

- Новая запись — новый файл `docs/development/observations/YYYY-MM-DD-краткое-имя.md`: дата случая и латинский slug по названию, заголовок первого уровня. Индекса у журнала нет, дописывать запись больше никуда не нужно.
- Существующая запись того же сигнала дополняется ссылкой на новый случай и сменой статуса, а не дублируется.
- Запись сдаётся как обычное изменение репозитория — по правилу контура из корневого [AGENTS.md](../../AGENTS.md).
- Перевод наблюдения в правило — решение владельца ([design-process.md](../development/design-process.md)): запись не правит `docs/standards/`, `AGENTS.md` и тексты скиллов.

## Другие адресаты

Не всё, что стоит сохранить после работы, — наблюдение:

- **Разбор незнакомой технологии** — skill `proj-record-learning`, раздел [docs/learning/](../learning/README.md) с реестром тем. Разбор не пишется для C#, F#, .NET, Aspire, Markdown, YAML, sh, justfile, Python-тулинга и правки документации: владелец этим владеет.
- **Принятое архитектурное решение** — [decisions.md](decisions.md).
- **Будущая работа** — задача в трекере по [issue-tracker.md](issue-tracker.md).
