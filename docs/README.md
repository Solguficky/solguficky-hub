# Документация Solguficky Hub

`docs/` хранит устойчивый контекст проекта: продуктовые ограничения, архитектуру, сервисные границы, инженерные стандарты и историю решений. Milestones, приоритеты, задачи и прогресс ведутся в Linear.

> На время синхронизации документации главным переходным контекстом остаётся [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md). После смыслового переноса его содержимого отдельным изменением будет решено, оставить ли компактный навигатор или архивировать документ.

## Статусы

Временной слой описывает систему:

- **Current** — фактически существует сейчас;
- **MVP** — требуется для первой живой сходки через бота;
- **Future** — направление после MVP, не текущий план реализации;
- **Legacy** — существующий код или дизайн, который не определяет новое направление.

Статус решения описывает зрелость выбора:

- **Accepted** — решение принято;
- **Open** — решение ещё должен принять владелец;
- **Superseded** — направление заменено или больше не применяется.

Статус документа:

- **Canonical** — активный источник правила или описания;
- **Draft** — материал для обсуждения;
- **Historical** — архивный срез.

## RFC, ADR и standard

- **RFC** помогает обсудить варианты до решения.
- **ADR** сохраняет принятое решение и ответ на вопрос «почему».
- **Standard** задаёт действующее правило, которое проверяется на review.

Принятый RFC может породить ADR, standard, оба документа или только изменение кода. Не каждое изменение требует всех трёх артефактов.

## Что не хранится в `docs/`

- копии Linear backlog и статусов задач;
- generated Protobuf-типы;
- подробные команды запуска конкретного сервиса — они живут в его README;
- инструкции конкретному AI-инструменту — они живут в skills и `AGENTS.md`;
- второй общий roadmap.
