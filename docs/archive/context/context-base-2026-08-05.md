> **Срез:** 05.08.2026
> **Статус документа:** переходный. Он существует, чтобы разнести содержимое по `docs/` и `CLAUDE.md`, после чего быть удалённым. Не превращать в постоянный файл — иначе появится второй источник правды.
> **Предыдущий срез:** canvas в docs — **устарел**, использовать только как источник фактов о состоянии кода, не о решениях.

## 1. Продукт

**Что это.** Telegram-бот сообщества: единое место правды о сходках — узнать что и когда, поучаствовать в подготовке, сохранить память о прошедшем. Не создавать шума в общем чате.

**Продуктовые принципы:**

- Тихий в чате — вся интерактивность в личке, в общем чате только обновляемый закреп
- Одна кнопка до главного — `/start` → ближайшая сходка
- Редактирование сообщений вместо отправки новых

**Цель v1.** Провести первый живой митап через бота. Критерий приёмки: регистрация прошла через бота, ручных правок в БД в день Х — **ноль**.

**Двойное назначение.** Продукт для сообщества + полигон для Event Sourcing, акторов и распределённых систем. При конфликте этих целей выигрывает продукт: учебный интерес не оправдывает срыв даты митапа.

## 2. Дельта решений: что отменено с 18.07

Это главный раздел. Всё, что ниже слева, встречается в текущей документации репозитория и должно быть исправлено.

| Было (канвас 18.07) | Стало (03.08) | Почему |
|---|---|---|
| `telegram-gateway` на **Rust** | **Go**, переписывание | Rust — максимальная цена языка при нулевой отдаче на часто меняющемся IO-клее |
| **Scala исключена** решением 17.07 | **Scala + Pekko** — аукцион v2 | Появился реальный слот: деньги, ES, конкурентность |
| **ADR-006: Railway** | **Мини-ПК** дома (Beelink EQ14/EQi12) | Railway дорожает и прячет инфраструктурную практику |
| **Kotlin → content-feed** | **Kotlin → только Android** | Слот JVM занят Scala; content-feed CRUD не учит ничему |
| **Go → scheduler** | Go занят гейтвеем | Один новый язык за раз |
| Ядро на C# | **F#** — домен `meetups` и identity | Нулевая инфраструктурная цена, инварианты в типах |
| `identity` — отдельный сервис (P2) | **Модуль внутри `meetups`** | Выделение оправдано только вторым потребителем |
| Ruby → админка (P2–P3) | **Ruby — условно**: read-only поверх read model, таймбокс 3 недели | Иначе это Rails-проект внутри пет-проекта |
| Деплой и observability — последними | **Деплой = M0** | Первый в жизни деплой не должен совпасть с неделей перед митапом |
| Аукцион — часть ядра | **Вне критического пути**, после первого митапа | Митап проводится без аукциона |

**Сквозной диагноз, который надо записать явно:** *инвертированная пирамида* — `notifications-service` и `websocket-gateway` написаны раньше сервиса, владеющего продуктовыми данными. P1 существует, чтобы её перевернуть.

## 3. Целевая архитектура

### 3.1 Сервисы

| Сервис | Язык | Состояние | Роль в v1 |
|---|---|---|---|
| `telegram-gateway` | **Go** | переписывается с Rust | Единственная точка входа: UI бота, FSM, роутинг апдейтов |
| `meetups` | **F#** + ASP.NET Core | не начат | Владелец продуктовых данных. Домен сходок + модуль identity/ролей |
| Mini App | TypeScript | не начат | Дизайн-первый: макеты → потом стек через ADR |
| `notifications` | C# net10 | каркас | Напоминания 24 ч / 2 ч — первый непридуманный сценарий |
| `auction` | C# · Akka.NET | **заморожен** | Вне v1. Судьба не решена — см. §8 |
| `websocket-gateway` | C# · SignalR | работает | Обслуживает только `auction:live`. Вне v1 — см. §8 |
| `nats-tester` | Python | работает | Инструментальный, e2e-проверки руками |
| `auction` v2 | **Scala + Pekko** | после митапа | Отдельный сервис, не миграция |
| `achievements` | **C# · Orleans** | после митапа | Полиглот-эксперимент на листовом сервисе |

### 3.2 Правило выбора языка

**Запрещённые комбинации** (каждая когда-то была в плане):

- Rust → gateway
- Go → доменное ядро или ES
- Kotlin → CRUD-сервис
- Elixir → data-пайплайн
- Python / Node → продуктовый бэкенд

### 3.3 Обмен

| | |
|---|---|
| **Асинхронное** | NATS, контракт Protobuf. Команды к stateful-агрегатам и события |
| **Синхронное** | gRPC мимо шины. CRUD и queries |
| **Критерий** | ADR-016 — остаётся в силе |
| **Контракты** | Protobuf-in-Git, без Schema Registry (ADR-014). Изменение `contracts/proto/` пересобирает всё в CI |

**Subjects:** `commands.<service>.<action>`, `events.<service>.<event>`. Подписка — многоуровневый wildcard (`events.auction.>`), одноуровневый не ловит ничего.

## 4. Тиры проектирования

Не все сервисы проектируются одинаково. Тир определяет глубину, а не важность.

| Тир | Признаки | Процесс | Бюджет |
|---|---|---|---|
| **T1** | Владеет данными · домен с инвариантами · несколько потребителей | D0–D8 полностью | 6–10 ч |
| **T2** | Понятная механика · один потребитель · нет домена | D0, D3, D5, D6 | 2–3 ч |
| **T3** | Механика очевидна · нет решений с последствиями | Пара абзацев в issue | 20 мин |

| Сервис | Тир |
|---|---|
| `meetups`, identity, `auction` v2 | T1 |
| `scheduler`, `notifications`, `telegram-gateway`, `achievements`, Mini App | T2 |
| `websocket-gateway`, ops-тулинг | T3 |

**Самопроверка:** если на вопрос «какие тут варианты решения» ответ «а какие варианты, тут всё очевидно» — это T3, и полный процесс будет имитацией.

## 6. Техдолг и открытые баги

### 6.1 Контрактные — чинить до новых фич

| Баг | Где |
|---|---|
| JSON вместо Protobuf | `SendMessageCommand` и `bid_placed` в гейтвее. При переписывании на Go — не переносить |
| Дублирование outbid-уведомлений | Два пути отправки вместо одного |
| Реальный gRPC-клиент отсутствует | Данные из `MockAuctionService` |

### 6.2 auction-service (заморожен, но долг записан)

- Нет EF-миграций: таблица `lots` не создаётся на чистой БД
- DI-баг: scoped-репозиторий в singleton-хендлере
- Фазы `NotStarted → OpenBidding → Idle → Final` — рефакторинг не закончен
- Деньги в `double` вместо `decimal`

### 6.3 Сквозное

| | |
|---|---|
| **JetStream** | Сейчас core NATS — at-most-once, сообщения теряются при рестарте подписчика. Требует durable consumers и идемпотентности разом |
| **Идемпотентность** | Поле `op_id` есть, не проверяется |
| **Read model** | Вместо ask-запросов к акторам |
| **Observability** | Loki/Grafana локально, метрики, трейсы |

## 8. Решения, которые ещё не приняты

Не закрывать их этим документом — это работа для D0–D8, не для переноса контекста.

| Вопрос | Почему это важно сейчас |
|---|---|
| **Судьба C#/Akka.NET `auction-service`** | Аукцион v2 уходит на Pekko отдельным сервисом. Значит существующий сервис — архив, эталон для сравнения или база для миграции? Пока не решено, он висит замороженным кодом в main |
| **Судьба `websocket-gateway`** | Обслуживает только `auction:live`. Если аукцион вне v1 — сервис не нужен в v1 вообще. Держать работающим или заморозить? |
| **Кто делает напоминания в M4** | `scheduler` был отдан Go, Go ушёл на гейтвей. Варианты: модуль внутри `notifications`, отдельный сервис, Quartz внутри `meetups` |
| **Стек Mini App** | ADR после первых утверждённых макетов, не раньше |
| **Когда включать JetStream** | Хорошее упражнение, но требует durable consumers и идемпотентности одновременно |

## 9. Что положить в `CLAUDE.md`

`CLAUDE.md` — инструкция агенту, а не место для стратегии. Держать коротким.

**Включить:**

- Стек по сервисам (таблица §3.1) — чтобы агент не писал C# там, где F#
- Границы: что **нельзя** трогать без явного запроса — `contracts/proto/`, создание новых сервисов, ADR
- Команды сборки, тестов, запуска
- Правило контрактов: изменение proto = отдельный коммит + пересборка всех потребителей
- Ссылку на каталог ADR
- Правило из ADR-013: доки правятся в том же изменении, что и код

**Не включать:**

> **Гайд по процессу проектирования (D0–D8, тиры) — не кладётся в `CLAUDE.md`.**
> Это твой процесс, а не агента. Договорённость: черновик пишешь ты, Claude работает оппонентом. Если документ попадёт в контекст агента как инструкция, агент начнёт проектировать сам — и разворот ролей, ради которого всё затевалось, исчезнет. Пусть лежит в `docs/` как личный процесс.
>
> Три разрешённых режима работы с агентом: **оппонент** (после своего черновика), **справочник** (факты о незнакомой технологии), **расширение списка вариантов**. Запрещённый режим — «прими решение за меня».
>
> Проверка, что не сжульничал: закрыть чат и пересказать решение вслух с обоснованием. Не можешь объяснить, почему отвергнута альтернатива — решение не твоё.

## 11. Анти-скоуп

Решено **не делать**, чтобы пет-проект не утонул:

- Настоящие платежи, эскроу, депозиты — только счёт-инструкция с ручным подтверждением
- Клиенты вне Telegram
- Публичность за пределами сообщества
- Мультитенантность

**Поведенческий анти-скоуп** (сюда же смотреть при планировании недели):

- Начинать с приятного вместо скучного — деплой скучнее, чем новый сервис на Go, и именно он отделяет мидла от техлида
- Мета-работа: строить систему организации проектов вместо проектов
- Переписывание вместо деплоя
- Полиглотность как позиция: план «8 сервисов на 6 языках» ты бы завернул подчинённому
