# Published

Страницы с публичным адресом на сайте сообщества — <https://solguficky.netlify.app>. Раздел не является источником правды: он показывает наружу материал, правду о котором хранит документ-источник. Одно исключение — то, что читатель заполняет прямо на странице «Аукцион 2026»: у заполненного документа-источника нет, и хранится оно вне репозитория ([ADR-042](../decisions/ADR-042-published-page-notes-own-backend.md)).

Правило одно и без исключений: **каталог — это адрес, страница всегда `index.html`**. Путь до файла минус `index.html` читается как URL буквально, без операции «отбрось расширение».

## Состав сайта

| Адрес | Страница | Связанный документ |
|---|---|---|
| `/` | [index.html](index.html) — индекс сайта | — |
| `/auction-2026` | [auction-2026/index.html](auction-2026/index.html) — «Аукцион 2026», страница обсуждения формата и фич | [RFC-007](../rfcs/RFC-007-auction-scope-and-format-options.md) |
| `/archive/auction-module` | [archive/auction-module/index.html](archive/auction-module/index.html) — презентация прошлой реализации, состояние на 28.10.2025 | [исходник в Marp](../archive/services/auction-module-slides.md) |

Колонка «Связанный документ» — обратная сторона связи: сама страница на репозиторий не ссылается, потому что на сайте относительного пути в репозиторий не существует.

## Заметки на странице «Аукцион 2026»

Условие «страница самодостаточна» касается чтения: страница открывается по ссылке без установки и логина, и весь её текст доступен без JavaScript. Заполняемые поля — надстройка над этим, и с появлением [Community site API](../../apps/community-site-api/README.md) заполненное перестало быть привязанным к одному браузеру: оно живёт документом на сервере по адресу `/api/notes`, у документа есть история версий и возврат к любой из них. Решение и его цена — [ADR-042](../decisions/ADR-042-published-page-notes-own-backend.md).

Правки уезжают на сервер сами, без кнопки «сохранить», и версией при этом не становятся: версию человек фиксирует явно, подписью. Возврат к версии ничего не теряет и в этом случае — то, что было набрано после последней версии, страница сначала убирает в историю записью «Состояние перед возвратом».

Логина по-прежнему нет. Пропуск к документу — его идентификатор в ссылке, и кнопка «Скопировать ссылку» отдаёт её целиком. Параметр `?doc=` страница убирает из адресной строки сразу после чтения: пропуску не место в истории браузера.

Без функции страница работает как раньше — заполненное остаётся в браузере, а панель заметок честно говорит, что сервер недоступен. Поэтому `npx --yes serve docs/published` и `python -m http.server` остаются годным способом посмотреть раскладку сайта.

## Почему каталог, а не `имя.html`

Плоский `auction-2026.html` отдаётся по `/auction-2026` только пока в панели Netlify включена оптимизация ассетов, срезающая расширение. Её можно выключить кнопкой, и адреса станут `404`, а в репозитории при этом ничего не изменится. Каталог с `index.html` отдаётся по своему пути обычным разрешением индекса каталога — на Netlify, на GitHub Pages и на `python -m http.server`. Корректность адресов живёт здесь, а не в чужой панели.

Побочное следствие: сайт проверяется локально одной командой из этого каталога.

```sh
npx --yes serve docs/published
```

## Что сюда попадает

Материал берётся в раздел, когда выполнены три условия сразу:

- у него есть читатель вне репозитория и обещанный ему адрес;
- страница самодостаточна: открывается по ссылке без установки и логина;
- источником правды она не является — правду хранит документ, который её породил. Заполняемые поля под это условие не подпадают: у заполненного документа-источника нет по построению.

HTML без публичного адреса сюда не переезжает и остаётся рядом с текстом, который его открывает: [architecture/decision-matrix.html](../architecture/decision-matrix.html), [design/bot/storyboard.html](../design/bot/storyboard.html), [archive/snapshots/project-canvas-2026-07-18.html](../archive/snapshots/project-canvas-2026-07-18.html).

`published/archive/` — сегмент адреса сайта, а не раздел [archive/](../archive/). Историческую пометку несут адрес и строка таблицы выше.

## Как добавить страницу

1. Создай каталог с адресом и положи в него `index.html`.
2. Добавь карточку на страницу [index.html](index.html): корневой индекс собран руками, и новая страница сама в нём не появится.
3. Впиши строку в таблицу состава.
4. Сошлись на страницу из документа-источника и назови источник в колонке связи.

Шаг 2 гейт не проверяет: он ловит ссылку без страницы, но не страницу без ссылки. Каталог, забытый в индексе, опубликуется и останется достижимым только по прямому адресу.

Workflow и его `paths` при этом не трогаются: публикуется весь каталог. Проверку раскладки и разрешимость ссылок держит `tools/community-site/check-published-pages.sh` — он в `just verify` и в CI.

Markdown на сайт не едет: шаг сборки удаляет `*.md` из копии каталога. Этот файл существует для читателя репозитория, а не для читателя сайта.

Как устроена доставка — [development/ci.md](../development/ci.md).
