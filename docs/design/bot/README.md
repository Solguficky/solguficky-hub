# Дизайн Bot UI

Здесь живут макеты интерфейса Telegram-бота. Процесс тот же, что и для [Mini App](../mini-app/README.md): сценарий и состояния экрана обсуждаются до выбора деталей реализации, макет утверждается здесь и только потом превращается в задачи.

## Материалы

| Файл | Статус | О чём |
|---|---|---|
| [storyboard.html](storyboard.html) | Draft | Кадры Bot-only интерфейса MVP: путь солегуфика, путь администратора, ошибки и служебные состояния |

## Правила

- Макет статический: HTML и CSS без JavaScript, backend и подключения к Telegram.
- Оформление следует дизайн-системе Organic.
- В кадре используются только те элементы, которые бот действительно умеет; список механик Bot API зафиксирован в самом storyboard.
- Кадр помечается как решённый, гипотеза или открытый вопрос. Решённым он становится вместе с изменением [product/overview.md](../../product/overview.md), ADR или требований сервиса.
- Storyboard не является контрактом хранения или API. Доменные решения принимаются в briefs сервисов и ADR.
- Точки расширения обозначаются раньше самих расширений: слот модулей сходки показан как место в интерфейсе и набор правил, без проектирования конкретного модуля.
- PNG-экспорты кадров не хранятся: источником правды остаётся HTML.
