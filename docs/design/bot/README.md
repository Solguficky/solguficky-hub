# Дизайн Bot UI

Здесь живут макеты интерфейса Telegram-бота. Процесс тот же, что и для [Mini App](../mini-app/README.md): сценарий и состояния экрана обсуждаются до выбора деталей реализации, макет утверждается здесь и только потом превращается в задачи.

| [design-code.md](design-code.md) | Canonical | Правила экранов обоих ботов с областью действия у каждого раздела; в боте хаба реализованы, в боте аукциона нет: дерево и возврат, клавиатура, доставка результата, вопросы, формат, ожидание; как правила ложатся на экраны аукциона, показ фото лота и расхождения сегодняшнего кода; что проверено на клиентах |

## Правила

- Макет статический: HTML и CSS без JavaScript, backend и подключения к Telegram.
- Оформление следует дизайн-системе Organic.
- В кадре используются только те элементы, которые бот действительно умеет; список механик Bot API зафиксирован в самом storyboard.
- Кадр помечается как решённый, гипотеза или открытый вопрос. Решённым он становится вместе с изменением [product/overview.md](../../product/overview.md), ADR или требований сервиса.
- Storyboard не является контрактом хранения или API. Доменные решения принимаются в briefs сервисов и ADR.
- Точки расширения обозначаются раньше самих расширений: слот модулей сходки показан как место в интерфейсе и набор правил, без проектирования конкретного модуля.
- PNG-экспорты кадров не хранятся: источником правды остаётся HTML.

## Реализация и макет

Треки storyboard против экранов бота в `apps/hub-bot/src/presentation/` после перевёрстки по дизайн-коду ([PER-444](https://linear.app/anticnvm/issue/per-444)). Колонка storyboard описывает нарисованный кадр; где текст макета под кадром уже говорит то же, что бот, строка так и помечена. Пометки кадров и статус Draft самого storyboard этой сверкой не меняются: кадр становится решённым по правилу выше, а не по факту реализации. Читателю вне репозитория бота описывает страница [published/hub-mvp/index.html](../../published/hub-mvp/index.html) (адрес сайта `/hub-mvp`); эту таблицу она не пересказывает: макет вне репозитория не обсуждался. Что из сценариев подтверждено живым прогоном, держит [local-development.md](../../development/local-development.md), а не этот раздел.

Без изменений: навигация варианта B, текст закрытого доступа (P-17), кадр недоступного сервиса (E-05), слот модулей — пустой. Текст ожидания допуска (P-14) получил второй вариант — для человека с ником, без кода заявки. Мелочи, которых в таблице нет: кнопки «Обновить» у списков сходок и пометки «(перенесена)» в списке нет; в карточке появились постеры каруселью.
