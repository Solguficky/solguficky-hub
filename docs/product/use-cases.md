# Словарь продуктовых сценариев

> **Статус:** Canonical. Документ задаёт стабильные имена продуктовых сценариев для поля `use_case`. Сценарии за пределами утверждённого среза не именуются.

Словарь задаёт стабильные значения поля `use_case` в структурных логах. Он растёт вместе с продуктом: имя появляется только для сценария, который уже входит в утверждённый срез.

## Граница сценария

Один `use_case` называет самостоятельную продуктовую цель человека. Он может охватывать несколько действий, технических цепочек и `request_id`, если все они ведут к одной цели. Отдельное имя требуется, когда сценарий:

- прямо соответствует продуктовому сценарию, а не шагу интерфейса;
- сохраняет смысл при смене экранов и транспорта;
- имеет самостоятельный наблюдаемый результат для человека;
- не является только этапом более крупного сценария из того же среза.

Кадры одного взаимодействия, этапы составного пути, варианты результата, транспортные операции и виды отказа отдельными `use_case` не становятся. Их различают состояние ответа, поле `operation` и поля результата записи. Поэтому пустой и непустой список относятся к одному сценарию, а создание черновика, заполнение формы и публикация не дробят создание сходки. Имя `use_case` выводится из доменной цели человека. Транспорт не диктует продуктовую спецификацию: лексическое совпадение с именем операции допустимо и само по себе не повод переименовывать сценарий.

Каждое действие внутри составного сценария получает свой `request_id`, но сохраняет общее значение `use_case`. Так записи нескольких запросов можно собрать по продуктовой цели, а конкретный исполнявшийся код по-прежнему различает `operation`.

## Первый вертикальный срез

Имена соответствуют сценариям «Создать сходку», «Найти сходку» и «Посмотреть актуальную информацию» из [основных сценариев MVP](overview.md#основные-сценарии-mvp) и ходу [первого вертикального среза](../architecture/first-slice.md#ход). Кадры макета и внутренние вызовы сервисов отдельными именами не становятся.

| `use_case` | Действие человека | Наблюдаемый результат |
|---|---|---|
| `create_meetup` | Создать новую сходку: завести черновик, заполнить данные и опубликовать | Сходка опубликована, стала видна и показана ссылка на неё |
| `find_meetup` | Просмотреть доступные новые сходки | Показан пустой список либо список видимых сходок |
| `view_meetup` | Открыть выбранную сходку | Показана карточка с актуальными данными |

| Шаг хода среза | `use_case` |
|---|---|
| `/start` и повторное открытие списка, в том числе пустого | `find_meetup` |
| Deep link `m_<uuid>` и открытие выбранной сходки | `view_meetup` |
| Вход в управление, черновик, форма и нажатие «Опубликовать» | `create_meetup` |

Нажатие «Опубликовать» и вся вызванная им техническая цепочка относятся к `create_meetup`: это завершение создания, а не отдельная продуктовая цель.
