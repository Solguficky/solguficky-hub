# ADR-010: Архитектура гибридного аукциона (Клиентские приложения)

> **Текущая применимость:** Superseded. Экран зала заменён [ADR-040](ADR-040-auction-screen-sse.md): SSE живёт внутри Auction Service, посредник `Real-Time Hub` не вводится. Admin Panel как Telegram Mini App вытеснена [mini-app.md](../services/mini-app.md): Mini App отложен решением владельца и возвращается только под сценарий, который не помещается в бота, поэтому консоль аукциониста не спроектирована. Третьего клиента этот ADR не знал: место участника в аукционе занимает не его решение, а [ADR-044](ADR-044-two-telegram-bots-and-shared-auction-screens.md) — два Telegram-бота с общим слоем экранов.

*   **Дата:** 22.10.2025
*   **Решение:** Для поддержки гибридного (офлайн/онлайн) формата аукциона будут созданы два специализированных фронтенд-приложения:
    1.  **Admin Panel:** Реализуется как **Telegram Mini App**.
    2.  **Big Screen App:** Реализуется как **стандартное Web App**.
*   **Обоснование:** Этот подход позволяет сохранить "живой" вайб аукциона, дополняя его технологиями. **Admin Panel** в виде Mini App решает ключевую проблему безопасной и бесшовной аутентификации ведущего, предоставляя ему богатый UI для управления торгами. **Big Screen App** служит "окном" в онлайн-мир для офлайн-участников, визуализируя ход торгов в реальном времени. Оба приложения взаимодействуют с бэкендом через `Real-Time Hub`.
