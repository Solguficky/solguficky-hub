# ADR-014: Упрощенное управление контрактами (Protobuf-in-Git) для MVP

*   **Дата:** 23.10.2025
*   **Статус:** Принято
*   **Контекст:** В ADR-008 было принято решение использовать Apicurio Registry для управления схемами сообщений. В ходе реализации MVP стало очевидно, что развертывание и поддержка дополнительного сервиса (реестра схем) является избыточной сложностью на данном этапе. У нас планируется только одна версия контрактов, и онлайн-проверка совместимости пока не требуется.
*   **Решение:** На этапе MVP отказаться от использования внешнего Schema Registry (Apicurio). Использовать подход **"Protobuf-in-Git"**.
*   **Обоснование:**
    - **Простота:** Исходные `.proto` файлы являются единственным источником правды и хранятся в монорепозитории в директории `contracts/proto`.
    - **Минимальные зависимости:** Сервисам не нужен дополнительный компонент в runtime для работы с контрактами.
    - **Надежность сборки:** Кодогенерация происходит на этапе сборки сервиса (build time), что гарантирует соответствие кода и контракта.
    - **Эволюция:** Когда потребуется поддержка нескольких версий контрактов и онлайн-проверка совместимости, можно будет вернуться к рассмотрению Apicurio или аналогичного решения, не переписывая уже существующие контракты.
*   **Последствия:**
    - Это решение заменяет ADR-008.
    - Из NATS-сообщений убирается заголовок `schema-id`, так как версионирование на данном этапе не требуется.
    - `docker-compose.yml` и конфигурации сервисов упрощаются, так как из них удаляется Apicurio Registry.
