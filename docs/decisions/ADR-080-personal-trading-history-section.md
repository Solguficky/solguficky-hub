# ADR-080: Личная история торгов участника — раздел меню «Мои торги», покупки на существующих чтениях, ставки через новое чтение Auction

> **Дата:** 2026-10-30  
> **Статус:** Accepted

## Контекст

Прогон stage 29.10.2026 ([PER-795](https://linear.app/anticnvm/issue/per-795)) показал: у участника есть «Ставки» одного лота, «Мои счета» одного аукциона и «Прошедшие» аукционы, но нет места, где видно своё по всем аукционам. Владелец спросил, где такая история ([PER-820](https://linear.app/anticnvm/issue/per-820)).

Что есть в коде на 2026-10-30:

- Личные чтения Auction привязаны к одному аукциону: `ListMyInvoices` и `GetMyPredictions` принимают `auction_id` (`contracts/proto/auction/v1/auction_service.proto`). Чтения «все мои ставки» нет.
- `ListAuctions` с `AUCTION_LISTING_FINISHED` отдаёт общий список прошедших аукционов, не по участнику.
- В read model `lot_bid` нет индекса по `participant_id` (`apps/auction/src/main/resources/db/migration/V5__lot_projection.sql`), у `auction_invoice` есть индекс `(auction_id, winner_id)` (`V17`).
- Бот хранилища не имеет ([ADR-030](ADR-030-telegram-bot.md)).
- `participant_id` в `lot_bid` и `winner_id` счёта — сам identity id платформы (`Viewer.identity_id`), отдельного псевдонима нет. Путь удаления субъекта [ADR-045](ADR-045-auction-scala-pekko-persistence-jdbc.md) («стереть связь identity → participant_id в Identity») в коде не существует; потребителя факта удаления субъекта в Auction нет, `PredictionStore.erase` вызывать некому.

## Варианты

Допущение, общее для вариантов: история считается на лету из существующих read model и ничего нового не хранит. Оно не обсуждается: хранилище копии личных данных противоречит минимизации ([ADR-059](ADR-059-auction-participant-display-name.md), [ADR-030](ADR-030-telegram-bot.md)).

- **А.** «Аукционы» → «Прошедшие» → аукцион → «Мои итоги»: личное внутри каждого завершённого аукциона, общего списка нет.
- **Б.** Отдельный раздел меню «Мои торги» с общим списком по аукционам.
- **В.** «Настройки» → «Мои данные».

Содержание: (а) покупки и счета (данные есть); (б) ставки по лотам с итогом «лидирую / перебили / выиграл» (нужно новое чтение Auction и индекс).

## Решение

Владелец выбрал 30.10.2026 вариант Б поэтапно:

1. **Раздел меню «Мои торги»** в обоих ботах, общий список по аукционам, свежие сверху.
2. **Этап 1 — «Покупки»:** выигранные лоты и счета по всем аукционам, только в боте на существующих чтениях (`ListAuctions`, `ListMyInvoices`, снимок лота); Auction и контракт не меняются. Цикл по аукционам ограничен числом и идёт параллельно, чтобы уложиться в бюджет действия 5 секунд ([design-code](../design/bot/design-code.md)).
3. **Этап 2 — «Ставки»:** новое чтение Auction `ListMyBids` (контракт, `proj-change-contract`) и индекс `lot_bid(participant_id)`; экран показывает свои ставки по лотам и итог по лоту.
4. Прогнозы остаются во вкладке «Прогнозы» аукциона ([PER-813](https://linear.app/anticnvm/issue/per-813)).
5. Отдельной задачей провязывается удаление субъекта Identity → Auction (имя, прогнозы, судьба `participant_id` в журнале).
6. Все задачи реализации — после финала 31.10.2026.

Показывается только своё: названия лотов, цены, статусы; чужих имён нет.

## Обоснование

**Почему Б.** Вопрос владельца — «где вся история»; один вход с общим списком отвечает на него, А даёт историю по одному аукциону, В прячет её в настройках, где её не ищут.

**Почему поэтапно.** Покупки закрывают главное ожидание («что я выиграл, сколько, оплачено ли») без изменений Auction и контракта; ставки требуют нового чтения, индекса и проверки контракта, и до финала это лишний риск.

**Почему удаление отдельной задачей.** Личная история новых данных не хранит и удаления не усложняет, но делает заметным пробел, который есть и без неё: `participant_id` журнала — identity id, потребителя события удаления нет. Решение, как обезличить журнал, — отдельное и его принимает владелец.

## Последствия

### Что становится проще

- У участника один вход к своим покупкам и ставкам по всем аукционам.
- Этап 1 — только бот, без миграции и контракта.

### Что становится сложнее

- Цикл по аукционам в боте упирается в бюджет 5 секунд: нужен предел числа аукционов и частичный ответ.
- Этап 2 добавляет метод в контракт, индекс в `lot_bid` (аддитивная миграция) и экраны в оба бота.
- Пока удаление субъекта не провязано, история отдаёт данные по identity id, а строки журнала после удаления человека остаются.
- Раздел пересекается с «Итогами» аукциона ([PER-813](https://linear.app/anticnvm/issue/per-813)): общая сводка и личная история должны делить тексты.

## Предсказание и пересмотр

Ожидаем, что после финала участники смотрят «Покупки» чаще «Ставок» и что аукционов у участника единицы.

Пересматриваем, если:

- цикл по аукционам не укладывается в бюджет действия — тогда общее чтение «мои покупки» в Auction;
- участники просят ставки раньше покупок;
- решение об удалении субъекта изменит смысл `participant_id` в журнале.
