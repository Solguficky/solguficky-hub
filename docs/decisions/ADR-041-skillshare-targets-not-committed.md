# ADR-041: Таргеты skillshare не хранятся в Git

> **Дата:** 2026-09-13  
> **Статус:** Accepted

## Контекст

Скиллы агента живут в репозитории двумя слоями. Источник — `.skillshare/skills/`: свои `proj-`скиллы в Git, внешние объявлены в `.skillshare/config.yaml` и ставятся `skillshare install -p` мимо Git. Таргеты — `.claude/skills/` и `.agents/skills/`: копии, которые раскладывает `skillshare sync -p`. До этого решения в Git лежал и источник, и копия: каталоги `proj-*` обоих таргетов плюс служебный `.skillshare-manifest.json` каждого.

Закоммиченная копия обошлась четырьмя счетами, два из которых подтверждены журналом наблюдений дважды каждый:

- манифест дрожит между машинами. Отпечатки `managed` считаются по сырым байтам и расходятся между LF и CRLF, `mtimes` хранит наносекунды файловой системы, `updated_at` переписывается даже холостым sync. Честный sync на Windows давал 62 строки бессмысленного диффа, и в этом шуме потерялась настоящая правка: `install` вычеркнул строки из `config.yaml`, и это заметили только по `git status`;
- состав таргетов зависит от способа создания дерева. Дерево от приложения получает `.claude/` целиком, дерево от `git worktree add` — только содержимое Git, и `check-generated.sh` печатал 52 строки «missing target» на пустом диффе;
- `sync` в дереве без внешних источников считает закоммиченные копии осиротевшими и удаляет их. Проверено `--dry-run` в рабочем дереве задачи: `52 pruned` на каждый таргет, причём в `git status` это не видно — каталоги погашены `.gitignore`;
- правка одного `proj-`скилла попадает в pull request тремя копиями: источник и два таргета.

## Варианты

**1. Оставить копию в Git и канонизировать манифест.** Приводить закоммиченный манифест к форме «только имена, значения пустые» рецептом поверх `sync` и требовать эту форму проверкой. Исходный план задачи.

**2. Не хранить таргеты в Git.** В репозитории остаётся только источник; копии собираются командой на каждой машине.

**3. Не хранить в Git ничего от skillshare, включая `proj/`.** Свои скиллы тоже уезжают во внешний источник.

## Решение

Вариант 2. Таргеты skillshare — сгенерированный артефакт. В Git хранится источник `.skillshare/` и объявление зависимостей; `.claude/skills/` и `.agents/skills/` вместе с их манифестами не коммитятся.

## Обоснование

Копия не добавляет доступности. Проверено на свежем клоне `develop`: после удаления обоих таргетов `skillshare sync -p` без сети и без `install` разложил все 16 `proj-`скиллов из источника в Git — `16 new, 0 pruned` на каждый таргет. Внешние скиллы требуют сети в любом варианте, потому что их источников в Git нет и не было.

Единственный аргумент за хранение манифеста оказался историческим. Проверка `check_manifest_entries` появилась коммитом `24f42d8` (#57) как реакция на скилл, молча выпавший из манифеста при сломанном frontmatter. Следующим же коммитом `439b87c` (#58) появился `check-frontmatter.sh` — прямой детектор той же причины, который читает источники и от манифеста не зависит. Косвенная проверка осталась широкой слабой сетью поверх узкой сильной, а не единственной защитой.

Вторая проверка, `compare_tree`, сверяет копию с источником и ловит правку скилла без `sync`. Без копии сверять нечего, а сама правка по-прежнему читается в диффе источника — теперь ровно один раз вместо трёх.

Вариант 1 снимал шум значений, но не снимал ни зависимость состава от машины, ни асимметрию таргетов, ни риск `sync` снести закоммиченное. Он чинил симптом и оставлял механизм.

Вариант 3 отвергнут: `proj-`скиллы — текст этого репозитория, они ревьюятся вместе с нормативом, на который ссылаются, и их отсутствие в Git сделало бы работу в свежем клоне невозможной без сети.

## Последствия

### Что становится проще

- Манифест исчезает из Git, и дрожать становится нечему. Задача канонизации отпадает целиком.
- Асимметрия между таргетами перестаёт быть наблюдаемой: закоммиченного состава, с которым её сравнивают, больше нет.
- `sync` не может осиротить закоммиченную копию — её нет.
- Правка `proj-`скилла читается в pull request один раз.
- `check-generated.sh` теряет сверку таргетов и проверку манифеста, сохраняя сверку команд. (2026-09-16: и сверку команд забрал rulesync — рецептом `just check-commands`, — так что скрипт удалён целиком.)

### Что становится сложнее

- Свежий клон и дерево от `git worktree add` требуют `skillshare sync -p`, прежде чем у агента появятся его собственные скиллы. Команда одна и сети не требует, но её надо не забыть. Дерева от приложения это не касается: `.claude/` приходит к нему мимо Git.
- Репозиторий перестаёт хранить запись о том, какой текст скилла агент фактически исполнял. Цена уплачена частично и раньше: воспроизводимость уже держалась на поле `version` в `.skillshare/skills/.metadata.json`, которого у tracked-клонов нет — у них только `branch: main`.
- Правка объявления зависимостей остаётся единственным молчаливым каналом порчи и требует собственной обёртки над `install`: `config.yaml` и `.metadata.json` этим решением из Git не выносятся.

## Предсказание и пересмотр

Ожидаем, что отсутствие копий не заметят иначе как по одной дополнительной команде после клонирования.

Пересмотр по любому из двух сигналов:

- агент в облачном контуре не может выполнить `sync` до начала работы, и отсутствие скиллов в чекауте становится блокирующим ([PER-138](https://linear.app/anticnvm/issue/per-138));
- понадобилось восстановить по коммиту, какой именно текст скилла исполнялся в тот момент, и `version` в `.metadata.json` на этот вопрос не отвечает.
