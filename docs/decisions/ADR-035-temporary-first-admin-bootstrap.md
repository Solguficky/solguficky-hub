# ADR-035: Временный bootstrap первого администратора через конфигурацию

> **Дата:** 2026-09-08  
> **Статус:** Accepted

## Контекст

[ADR-026](ADR-026-identity-mvp-model-and-access.md) назначил выдачу глобальной роли администратора maintainer-операцией через защищённый служебный endpoint Identity и запретил Telegram user id в конфигурации как источник роли. Штатный путь требует сначала решить authentication endpoint в [PER-30](https://linear.app/anticnvm/issue/per-30); endpoint и его контракт ещё не существуют.

Первый вертикальный срез уже требует профиль с ролью администратора, чтобы проверить создание и публикацию сходки. В текущем состоянии Identity умеет создать профиль и прочитать активную роль, но не умеет выдать первую роль. Прямой SQL обходит границу сервиса, а отдельный CLI создаёт вторую временную привилегированную поверхность.

Решение требует отдельного ADR не из-за самой переменной конфигурации. Оно меняет семантику межсервисной операции `ResolveIdentity` и ограниченно отменяет явно принятый запрет ADR-026 в чувствительной границе авторизации. Обратный переход требует согласованно удалить эту семантику из Identity и эксплуатационных конфигураций только после того, как во всех нужных средах появится штатный путь выдачи первой роли.

## Варианты

| Вариант | Цена | Отношение к ADR-026 | Негативный исход |
|---|---|---|---|
| Перенести PER-30 и реализацию служебного endpoint в первый срез | выбрать service authentication, авторизацию операции и аудит; изменить контракт и реализовать endpoint | полностью следует выбранному штатному пути | первый срез блокируется security- и infrastructure-решением, которое может измениться после появления production-топологии |
| Временная maintainer-команда или CLI | реализовать, защитить, протестировать и затем удалить вторую привилегированную поверхность | сохраняет владельца операции, но нарушает выбор единственной поверхности через endpoint | временный интерфейс остаётся навсегда либо расходится по семантике с endpoint |
| Разовый прямой SQL | написать и выполнить runbook с ручной проверкой результата и отката | прямо нарушает запрет на штатное редактирование БД и обходит идемпотентную сервисную операцию | ошибка оператора или знание устаревшей схемы создаёт неверную роль; `granted_by` не подтверждает настоящего субъекта |
| Локальная запись роли только для проверки PER-40 | подготовить воспроизводимый fixture и удерживать его границу | не меняет ADR, пока не называется эксплуатационным bootstrap | срез выглядит зелёным, но чистая среда по-прежнему не умеет получить первого администратора |
| Один Telegram user id в конфигурации Identity | временно усложнить `ResolveIdentity`, AppHost, тесты и последующее удаление | ограниченно заменяет запрет Telegram id в конфигурации и endpoint-only bootstrap | конфигурация превращается в постоянный скрытый канал выдачи роли или восстанавливает отозванное право |

## Решение

До появления штатного служебного endpoint Identity принимает необязательную переменную `IDENTITY_ADMIN_TELEGRAM_USER_ID` с одним положительным Telegram user id. Отсутствующее или пустое значение отключает bootstrap; заданное некорректное значение не допускает запуск процесса.

После создания или разрешения соответствующего профиля Identity в той же транзакции один раз добавляет ему роль `admin`. Повторные и параллельные вызовы не создают вторую запись. Наличие любой прежней записи этой роли, включая отозванную, означает, что bootstrap уже состоялся: следующий `ResolveIdentity` роль не восстанавливает.

Значение переменной не является списком администраторов и не остаётся источником текущих прав. Удаление переменной после первой выдачи не отзывает роль; последующее состояние читается только из `identity_roles`. Значение Telegram id не пишется в лог.

Текущая схема требует `granted_by` как ссылку на профиль. Для bootstrap запись указывает на тот же профиль, которому выдаётся роль. Это техническая отметка bootstrap, а не доказательство аутентифицированного self-grant; полноценную атрибуцию maintainer-операции должен определить штатный endpoint.

Решение ограниченно заменяет ADR-026 в двух местах: временно разрешает один Telegram user id в конфигурации и временно выполняет первичную выдачу внутри `ResolveIdentity`. Обычные выдача и отзыв ролей по-прежнему принадлежат maintainer'у и должны выполняться защищённым идемпотентным endpoint. Прямой SQL не становится штатным путём.

Реализация вынесена в [PER-167](https://linear.app/anticnvm/issue/per-167).

## Обоснование

Bootstrap через конфигурацию сохраняет проверяемый путь от Telegram update до роли и не требует ручного редактирования данных. Он меньше служебного endpoint: не вводит новый контракт и не заставляет первый срез преждевременно выбирать service authentication, аудит и production-сетевую границу из PER-30.

Перенос endpoint архитектурно чище, но расширяет первый срез отдельным security-решением и его реализацией. CLI платит почти той же временной поверхностью при худшей эксплуатации. Прямой SQL зависит от знания схемы, обходит инварианты сервиса и оставляет среду ручным исключением. Локальная тестовая запись проверяет потребление роли, но не проверяет bootstrap чистой среды.

Абсолютный запрет ADR-026 был полезен против превращения временного списка Telegram id в постоянную модель ролей. Здесь исключение уже: одно значение, одна выдача, отсутствие восстановления после отзыва и заранее названный момент удаления.

## Последствия

### Что становится проще

- первый вертикальный срез воспроизводимо получает администратора без SQL, CLI и админского UI;
- повторный запуск и повторный `/start` не требуют ручной сверки роли;
- штатный endpoint можно спроектировать в PER-30 отдельно от проверки среза.

### Что становится сложнее

- `ResolveIdentity` временно не только устанавливает личность, но и выдаёт право;
- Telegram user id временно становится персональными данными конфигурации;
- `granted_by` не доказывает личность maintainer'а для bootstrap-записи;
- временный путь нужно удалить из кода, AppHost, документации и тестов вместе с появлением endpoint.

## Предсказание и пересмотр

Ожидается, что одного bootstrap-id хватит до реализации служебного endpoint и он будет использован только для первичной настройки среды.

Решение прекращает действовать, когда endpoint выдачи ролей из PER-30 доступен maintainer'у. В той же работе удаляются переменная, ветка выдачи из `ResolveIdentity` и связанная конфигурация. Решение пересматривается раньше, если требуется второй bootstrap-id, переменная начинает использоваться для восстановления отозванной роли или через неё регулярно меняют состав администраторов.
