# ADR-015: Использование Loki для централизованного сбора логов

> **Текущая применимость:** Superseded. Заменён [ADR-053](ADR-053-production-observability-otlp-better-stack.md): сервисы шлют OTLP в Collector на хосте, бэкенд продакшена — Better Stack. Предпосылка про Railway и log drains не сбылась, хостинг сменил [ADR-039](ADR-039-single-vps-for-initial-self-hosting.md). Локальные Loki и Grafana остаются диагностическим профилем `notifications-observability` и продакшен не описывают. Grafana Cloud перенесён в замену как запасной бэкенд с критериями перехода.

**Дата**: 2025-10-23

**Статус**: Принято

### Контекст

Проекту требуется единая система для сбора, хранения и анализа логов со всех микросервисов. Текущий подход, когда каждый сервис пишет структурированные логи в `stdout`, хорошо подходит для контейнеризированных сред, но не обеспечивает централизованного доступа и поиска.

Требования к системе:
- Поддержка развертывания в Railway и локальной разработки.
- Наличие UI для поиска и фильтрации.
- Open-source или наличие щедрого бесплатного тарифа.
- Минимальные изменения в коде существующих сервисов.

### Рассмотренные варианты

1.  **Loki + Grafana**: Open-source, стандарт индустрии, индексирует только метаданные, что делает его быстрым и экономичным. Отличная интеграция с Grafana.
2.  **Datadog / Better Stack**: SaaS-решения. Просты в настройке, но являются проприетарными и могут стать дорогими при росте объемов.

### Решение

Мы принимаем **Loki** в качестве основной системы для агрегации логов. Для визуализации будет использоваться **Grafana**.

На начальном этапе мы будем использовать **Grafana Cloud**, который предоставляет щедрый бесплатный тариф. Это позволит нам быстро развернуть систему без необходимости поддерживать собственную инфраструктуру. В будущем возможен переезд на self-hosted инстанс.

### Последствия

- **Позитивные**:
    - Все логи со всех сервисов будут доступны в одном месте (Grafana).
    - Мощный язык запросов LogQL для анализа логов.
    - Заложена основа для полноценной системы observability (можно будет легко добавить метрики Prometheus и трейсы Tempo в той же Grafana).
    - Не требуется изменять код сервисов, так как они уже пишут логи в `stdout`.

- **Негативные**:
    - Необходимо настроить отправку логов (log drains) из нашей среды развертывания (Railway) в Grafana Cloud.
    - Для локальной разработки потребуется настроить `docker-compose` с Loki и Grafana.
