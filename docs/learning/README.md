# Разборы кода

Раздел адресован читателю, а не системе. Здесь лежат разборы незнакомых технологий и решений этого репозитория: почему код выглядит именно так и почему выбран этот вариант, а не соседний.

Разбор не источник правды и в её таблицу не входит. Как устроен компонент — в [services/](../services/), почему так решено — в [decisions/](../decisions/), как обязательно делать — в [standards/](../standards/). При расхождении правы они. Комментарии в коде для объяснения не используются: объяснение живёт здесь.

С 2026-10-03 бот хаба называется Hub Bot: текущие пути — `apps/hub-bot`, рецепты — `just hub-bot-*`, настройки — `HUB_BOT_*` ([уточнение ADR-044](../decisions/ADR-044-two-telegram-bots-and-shared-auction-screens.md#уточнение-2026-10-03-полное-переименование-бота-хаба)). Записи о выполненных ранее экспериментах сохраняют прежние имена и результаты; обновление инструкций не означает нового прогона.

## Как устроено

Файл на тему, каталог на технологию: `go/`, `grpc/`, `protobuf/`, `postgresql/`, `orleans/`, `typescript/`, `biome/`, `grammy/`, `self-hosting/`, `helm/`, `scala/`, `nats/`, `mtcute/`, `opentelemetry/`. Каталог заводится вместе с первым разбором в нём, а не заранее.

Тема пополняется, когда её трогает новый код, и не заводится заново на каждую задачу. Разборы не привязаны к номерам Linear: одна тема набирается из многих срезов, один срез задевает несколько тем.

Разборы пишет скилл `proj-record-learning` по проверяемой опоре: предпочтительно по диффу ветки, а после обсуждения или диагностики без diff — по точным строкам прочитанного кода и выводу проверенной команды. Реестр ниже — его вход и его ограничитель: тему, которой в реестре нет, скилл заводит только с подтверждения владельца. Без этого правила реестр за пару месяцев расщепляется на синонимы одной темы.

Разбор адресован читателю, который разбираемую технологию не знает. Отсюда его блоки: **Механика** — примитивы языка и инструмента на строках из проверяемой опоры; **Урок** — что переносится на следующий сервис и другие стеки; **Почему так, а не иначе** — отвергнутые варианты и цена каждого; **Схема**; **Первоисточники**; **Проверь себя**. Абзац, который нельзя понять без знания технологии, разбором не является и переписывается.

Разбор объясняет технологию через код среза, а не пересказывает срез: перечисление появившихся функций даёт `git log`, а не понимание. Если решение пришло из скилла, скилл называется в «Первоисточниках» путём в `.skillshare/skills/` — рядом со спецификацией, а не вместо неё.

Статус ставится по факту, а не по ощущению:

- **разобрано** — объяснил вслух и не подглядывал;
- **поверхностно** — понял при чтении, но своими словами не собрал;
- **вернуться** — остались вопросы, и они записаны в самом разборе.

Различие между первыми двумя и есть смысл поля: чтение создаёт ощущение понимания, которое проверка не подтверждает.
