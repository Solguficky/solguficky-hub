# ТЗ (Живой документ): Notifications Service

## 1. Ответственность

Сервис является **централизованным "умным" обработчиком бизнес-событий** для информирования пользователей. Его основная задача — решать, **КОГО**, **О ЧЕМ** и **КОГДА** нужно уведомить.

Сервис инкапсулирует в себе всю бизнес-логику, связанную с уведомлениями:
1.  **Формирование контента:** Преобразует абстрактные бизнес-события (например, `LotSold`) в конкретные, человекочитаемые тексты сообщений (например, "Поздравляем, вы выиграли лот!").
2.  **Определение получателей:** На основе события определяет, кому нужно отправить сообщение (победителю, проигравшему, всем подписчикам).
3.  **Планирование отправки:** Управляет отложенными уведомлениями (например, "напомнить о сходке за час до начала").

Результатом работы сервиса является публикация готовой к отправке команды `commands.telegram.send_message` в шину NATS.

## 2. Технологии

*   **Язык:** Elixir
*   **Фреймворк:** OTP (для управления процессами-таймерами)
*   **NATS-клиент:** Официальный клиент Elixir
*   **Логирование:** Встроенный логгер Elixir

## 3. Архитектура

1.  **Подписка на события:** Сервис подписывается на широкий спектр бизнес-событий из NATS, которые могут потребовать реакции (например, `events.auction.lot_sold`, `events.event.created`).
2.  **Движок правил (Rule Engine):** Внутри сервиса находится логика (например, pattern matching по типу события), которая определяет, какое уведомление нужно сгенерировать.
3.  **Управление таймерами:** Для отложенных уведомлений сервис использует легковесные процессы Elixir/OTP для планирования отправки. Каждый "напоминание" может быть отдельным процессом, который "проснется" в нужное время.
4.  **Публикация команд:** После формирования текста и определения получателя, сервис публикует конкретную команду (например, `commands.telegram.send_message`) в NATS, которую подхватит и исполнит `Telegram Gateway`.

## 4. Внешние контракты (NATS)

### 4.1. Подписка на события (входящие)

*   `events.auction.bid_placed`
*   `events.auction.lot_sold`
*   `events.event.created`
*   ...и другие бизнес-события.

### 4.2. Публикуемые команды (исходящие)

*   **`commands.telegram.send_message`**
    *   *Получатель:* `Telegram Gateway`
    *   *Описание:* Прямая команда на отправку конкретного текста в конкретный чат.

## 5. Зависимости

*   Для формирования некоторых сообщений сервис может делать **синхронные gRPC-запросы** к другим сервисам для обогащения данных (например, запросить у `Identity Service` никнейм пользователя по ID).

## 6. Конфигурация

*   `NATS_URL`: Адрес сервера NATS.
*   `IDENTITY_SERVICE_GRPC_URL`: Адрес gRPC-сервера `Identity Service`.
