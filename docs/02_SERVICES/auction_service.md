# ТЗ (Живой документ): Auction Service

## 1. Ответственность

Сервис полностью отвечает за **проведение торгов** в рамках одной сходки. Он является "владельцем" всей бизнес-логики, связанной с аукционами.

## 2. Технологии

*   **Язык:** Scala (или F#)
*   **Фреймворк:** Akka с модулем Akka Persistence
*   **База данных:** PostgreSQL (для Event Sourcing)
*   **Коммуникация:** NATS (для команд/событий), gRPC (для запросов статуса)
*   **Сериализация:** Protobuf (схемы управляются через Apicurio Registry)

## 3. Ключевые фичи (Что должен уметь?)

*   **Управление жизненным циклом:** Поддерживает полный цикл аукциона, включая двухфазную модель (сбор ставок -> финал).
*   **Поддержка разных режимов торгов:**
    *   Классический онлайн (`Slotted Online`)
    *   Голландский (`Dutch Final`)
    *   Аукцион Викри (`Best & Final`)
*   **Продвинутая механика ставок:**
    *   Поддержка автоставок (`Proxy-bids`).
    *   Механизм анти-снайпинга.
*   **Гибкая конфигурация:** Позволяет задавать глобальные настройки и переопределять их на уровне каждого лота.
*   **Интеграция с гибридным форматом:** Предоставляет API и события для поддержки офлайн-финала с ведущим.

## 4. Внешние контракты (Как с ним общаться?)

*   **Асинхронный (NATS):**
    *   **Принимает команды** на запуск, изменение и завершение аукционов и лотов.
    *   **Публикует события** о ключевых моментах: старт, новая ставка, продажа лота, завершение.
    *   Все сообщения сериализуются в **Protobuf**. Схемы регистрируются в **Apicurio Registry**.
*   **Синхронный (gRPC):**
    *   Предоставляет API для **получения текущего статуса** аукциона (активный лот, цена, лидер).
    *   Контракты определены в `.proto` файлах.

## 5. Зависимости

*   Зависит от **Events Service** для получения и верификации информации о сходке, к которой привязан аукцион.

## 6. Ключевые сущности (Акторы)

*   **`AuctionSessionActor` (Агрегат: Аукцион):** Родительский персистентный актор-координатор. Управляет глобальными настройками и фазами аукциона для одной сходки. Создает и супервизит дочерние `LotActor`.
*   **`LotActor` (Агрегат: Лот):** Дочерний персистентный актор-исполнитель. Реализует всю сложную логику торгов для одного лота, включая режимы (Slotted, Dutch, Vickrey), анти-снайп и proxy-bids.

## 7. Обрабатываемые команды (входящие из NATS)

*   `commands.auction.start { eventId, settings }`
*   `commands.auction.place-bid { eventId, lotId, userId, amount }`
*   `commands.auction.admin.update-settings { eventId, settings }`
*   `commands.auction.admin.close-lot { eventId, lotId }`

## 8. Публикуемые события (исходящие в NATS)

*   `events.auction.started { eventId, lots }`
*   `events.auction.bid-placed { eventId, lotId, userId, currentPrice, leaderId }`
*   `events.auction.lot-sold { eventId, lotId, winnerId, finalPrice }`
*   `events.auction.finished { eventId }`

## 9. Синхронные API (gRPC)

*   `GetAuctionStatus(eventId) returns { status, activeLot, currentPrice, leader }`

## 10. Конфигурация (Переменные окружения)

*   `NATS_URL`: Адрес сервера NATS.
*   `APICURIO_REGISTRY_URL`: URL Apicurio Registry для получения Protobuf-схем.
*   `POSTGRES_URL`: Строка подключения к PostgreSQL (Event Store).
*   `GRPC_PORT`: Порт для gRPC-сервера.
