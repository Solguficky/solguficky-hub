# ТЗ (Живой документ): Real-Time Hub

## 1. Ответственность

Сервис является **транспортным шлюзом реального времени** между бэкенд-платформой и фронтенд-клиентами (такими как `Big Screen App` и `Admin Panel`). Его единственная задача — эффективно управлять WebSocket-соединениями и проталкивать в них релевантные события из шины NATS.

**Сервис НЕ должен содержать сложной бизнес-логики.** Он является "глупым", но сверхбыстрым прокси для событий.

## 2. Технологии

*   **Язык:** Elixir
*   **Фреймворк:** Phoenix (с использованием Channels/LiveView для WebSocket)
*   **NATS-клиент:** Официальный клиент Elixir
*   **Логирование:** Встроенный логгер Elixir

## 3. Архитектура

1.  **Подписка на события:** При старте сервис подписывается на широкий спектр событий в шине NATS (например, на все темы `events.auction.*`).
2.  **Управление WebSocket-соединениями:** Phoenix Framework нативно управляет жизненным циклом WebSocket-соединений от клиентов.
3.  **Механизм "каналов" (Channels):** Клиент при подключении по WebSocket "подписывается" на определенный канал, связанный с конкретной сущностью. Например: `auction:сходка123`.
4.  **Роутинг:** Когда сервис получает событие из NATS, он извлекает из payload идентификатор (например, `eventId: "сходка123"`) и проталкивает это событие только тем клиентам, которые подписаны на соответствующий канал (`auction:сходка123`).

## 4. Внешние контракты (API)

### 4.1. WebSocket API (Phoenix Channels)

*   **Эндпоинт:** `ws://<host>/socket`
*   **Протокол:** Клиент подключается и отправляет сообщение о подписке на канал.
    *   **Пример подписки клиента:** `{"topic": "auction:event-123", "event": "phx_join", "payload": {}, "ref": 1}`
*   **Проталкиваемые сообщения:** Сервер отправляет клиентам сообщения о событиях.
    *   **Пример сообщения от сервера:** `{"topic": "auction:event-123", "event": "new_event", "payload": {"event_type": "bid-placed", "data": {...}}}`

### 4.2. Взаимодействие с NATS

*   **Подписка на темы:**
    *   `events.auction.*`
    *   ...и другие темы, события из которых могут быть интересны фронтенду.

## 5. Зависимости

*   Сервис **не зависит** напрямую от других бизнес-сервисов. Его единственный источник информации — **шина сообщений NATS**.

## 6. Конфигурация

*   `NATS_URL`: Адрес сервера NATS.
*   `WEBSOCKET_PORT`: Порт для WebSocket-сервера Phoenix.
