# Контур исполнения задачи

> **Статус:** Canonical. Документ отвечает на один вопрос: что агент доводит до конца сам и где обязан остановиться.

Контур — режим работы над одной задачей Linear. Он открывается командой владельца на конкретную задачу, идёт до открытого pull request и на этом закрывается. Внутри контура агент коммитит, пушит и открывает PR без отдельного разрешения на каждый шаг. Вне контура он показывает `git status --short` и останавливается перед коммитом.

Ветвление, имя ветки и форма PR — [standards/git/branching.md](../standards/git/branching.md). Проектирование до реализации — [design-process.md](design-process.md); контур исполняет уже утверждённый срез.

## Когда контур открыт

Контур открыт, когда владелец назвал задачу Linear и запустил работу по ней командой `/proj-take-task PER-N`. Всё остальное — вне контура: правка по ходу разговора, эксперимент, ответ на вопрос, работа без задачи в трекере.

Признак открытого контура — текущая ветка. `feature/PER-N` означает, что контур открыт на задачу `PER-N`; любая другая ветка означает, что он закрыт. Признак живёт в репозитории, а не в диалоге, поэтому переживает сжатие контекста и рестарт сессии: агент читает его командой `git branch --show-current` и не полагается на память о разговоре.

Ветка задачи существует, но владелец её не открывал в этой сессии — контур всё равно открыт: он принадлежит задаче, а не сессии. Ветка задачи существует, а работа идёт по другой теме — контур на неё не распространяется.

Границы контура — границы названной задачи. Изменение, которого нет в её разделе «Что сделать», в контур не входит, даже если оно очевидно полезно.

## Последовательность внутри контура

Шаги 1–4 исполняет skill `proj-start-task`, шаги 5–9 — skill `proj-deliver-task`. Скиллы задают порядок работы и инструменты; правила ниже остаются каноном и в скиллах не дублируются.

1. Возьми идентификатор названной задачи Linear в верхнем регистре, выполни `git fetch origin` и создай ветку от `origin/develop`: для `PER-84` команда — `git switch -c feature/PER-84 origin/develop`. Формат и проверки — в [branching.md](../standards/git/branching.md).
2. Прочитай задачу и её комментарии, документы, на которые она ссылается, и текущее состояние затронутых файлов. Покажи, что прочитал.
3. Сработал чекпоинт — покажи план и дождись ответа. Не сработал — иди дальше.
4. Реализуй срез. Документация меняется тем же изменением, что и код.
5. Прогони `just verify` — механический гейт: agent tooling, Identity и тесты. Проверки, которых в нём нет, добери по `just --list`.
6. Прогони ревью перед PR: скилл `proj-review-change`.
7. Закоммить по [commit-messages.md](../standards/git/commit-messages.md).
8. Открой PR по [branching.md](../standards/git/branching.md).
9. Отчитайся: статус задачи и отклонения от плана. Отчёт называет отклонения явно, а не растворяет их в описании сделанного.

## Чекпоинты: план до кода

План показывается до правок и ждёт ответа владельца, когда:

- **развилка не зафиксирована** — задача допускает два решения с разными последствиями, и выбор не сделан ни в ADR, ни в самой задаче;
- **меняется норматив** — правка затрагивает `docs/standards/`, `AGENTS.md` или текст скилла. Норматив действует на всю дальнейшую работу, и цена молча принятой формулировки выше цены одного вопроса.

План называет развилку, варианты и рекомендацию. Список файлов планом не является.

## Стоп-триггеры: остановка до коммита

Работа останавливается на состоянии «правки есть, коммита нет», когда:

- **изменение вышло за границы задачи** — понадобилось тронуть то, чего в задаче нет;
- **реализация разошлась с утверждённым планом** — план перестал описывать то, что делается;
- **проверки красные, и чистого фикса нет** — причина не в изменении либо фикс тянет за собой правку вне границ задачи.

При остановке агент показывает `git status --short`, называет сработавший триггер и предлагает варианты. Обход триггера подгонкой проверок или расширением задачи на ходу — не вариант.

## Что остаётся за владельцем

- Ревью и мерж pull request. Ручными они остаются всегда.
- Решение по каждому чекпоинту и стоп-триггеру.
- Перевод статуса задачи, который не делает Linear сам по связанному PR.
