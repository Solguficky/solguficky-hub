# 2026-09-12 — Команды skillshare молча правят отслеживаемые файлы

- **Контекст:** PER-99, `skillshare install -p`, `.skillshare/config.yaml`, `.skillshare/skills/.metadata.json`.
- **Наблюдение:** `skillshare install -p` поставил 9 скиллов из 12 — `aspire-orchestration` заблокирован его собственным security audit с находкой уровня CRITICAL — и вычеркнул 2 строки из `.skillshare/config.yaml` и 19 из `.skillshare/skills/.metadata.json`. Оба файла отслеживаются. Отказ по одному скиллу в выводе был, а правка конфига — нет; она замечена только `git status --short`.
- **Последствие:** регрессия общего конфига едва не уехала в pull request с документацией, к которому отношения не имеет. Ни один гейт её не ловит: `check-agent-tools` читает таргеты и frontmatter, а не объявление зависимостей.
- **Адресат:** Автоматическая проверка — `tools/skillshare/`. Второй адресат — `AGENTS.md`, где `skillshare install -p` и `skillshare sync -p` описаны как безопасный путь после клонирования или создания дерева.
- **Повторение:** второй независимый случай — сессия «Check skillshare manifest hashes on Windows» от 2026-09-07 на ветке `feature/PER-140`, другое дерево и другая задача. Там `skillshare sync -p` после мержа переписал 62 строки в двух отслеживаемых манифестах. Причины разобраны экспериментом в изолированном проекте: хеши `managed` считаются по сырым байтам источника и расходятся между LF и CRLF на одном и том же содержимом, `mtimes` хранит наносекундные отметки файловой системы и различается между любыми двумя чекаутами, `updated_at` переписывается при каждом sync, включая холостой. Значения при этом не валидирует ни один гейт: подмена хеша на `deadbeef` дала побайтово идентичный вывод проверки, а добавленный позже `check_manifest_entries` намеренно спрашивает только наличие ключа. Пять записей из пятнадцати на develop не воспроизводятся ни из LF, ни из CRLF, то есть закоммиченный манифест уже разошёлся с собственными источниками. Команды разные, класс один: инструмент правит отслеживаемые файлы как собственное внутреннее состояние.
- **Следующий сигнал:** сигнал подтверждён дважды; дальше — формулировка правила, а не ожидание третьего случая.
- **Правило из двух случаев:** файл, который инструмент переписывает как локальный кеш и который не читает ни одна проверка, в Git не хранится — это про `.skillshare-manifest.json` в обоих таргетах. `config.yaml` и `.metadata.json` под правило не подпадают: они объявляют зависимости и остаются в Git, поэтому для них нужен обратный ход — правка после `install` должна быть заметной, а не молчаливой.
- **Перенесено:** [ADR-041](../../decisions/ADR-041-skillshare-targets-not-committed.md), раздел про скиллы в [AGENTS.md](../../../AGENTS.md) и рецепт `just skillshare-install` поверх `tools/skillshare/install.sh`. Правило применено шире формулировки: из Git ушёл не только манифест, а таргет целиком — отдельно хранить кеш инструмента внутри сгенерированного каталога оказалось нечего. Обратный ход для объявления зависимостей сделан как сказано: обёртка сверяет `config.yaml` и `.metadata.json` до и после `install` и падает, называя изменённый файл.
- **Статус:** переведено в правило
