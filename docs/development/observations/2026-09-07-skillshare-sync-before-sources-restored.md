# 2026-09-07 — `skillshare sync` запущен до восстановления внешних sources

- **Контекст:** настройка `proj-reflect-work`, команда `skillshare sync -p`; ранее тот же сигнал описан в [AGENTS.md](../../../AGENTS.md) в истории о fresh worktree.
- **Наблюдение:** в worktree не было внешних sources, объявленных в `.skillshare/config.yaml`. Запуск `skillshare sync -p` до `skillshare install -p` посчитал 49 copied skills в каждом из targets осиротевшими и удалил их. Восстановление потребовало установки sources и повторной синхронизации; оно также принесло нерелевантный drift служебных metadata и manifest-хешей, который пришлось отдельно убрать.
- **Последствие:** обычная раскладка project skills стала разрушительной операцией для локальной среды и увеличила объём проверки не связанными с задачей изменениями.
- **Адресат:** Автоматическая проверка — рецепт в `justfile` или скрипт в `tools/skillshare/`, который до sync проверяет наличие объявленных внешних sources и останавливается с командой `skillshare install -p`. Обычная инструкция в `AGENTS.md` уже есть и не предотвратила повторение; хук не подходит, потому что событие — ручной запуск команды.
- **Повторение:** второй независимый случай: в предыдущем fresh worktree тот же порядок удалил 46 записей manifest на target; случай описан в [AGENTS.md](../../../AGENTS.md).
- **Следующий сигнал:** agent tooling sync из worktree без внешних sources изменяет или удаляет target-каталоги до явного восстановления dependencies.
- **Перенесено:** проверка не понадобилась: причину сняло [ADR-041](../../decisions/ADR-041-skillshare-targets-not-committed.md). Таргеты в Git больше не лежат, и `sync` в дереве без внешних sources не находит закоммиченных копий, которые можно было бы признать осиротевшими. Опасной осталась другая команда, `install`, и её держит обёртка `just skillshare-install`.
- **Статус:** переведено в правило
