# 2026-11-20 — Брокер Codex пережил исполнителя и не дал снять каталог дерева листа

- **Контекст:** эпик [PER-917](https://linear.app/anticnvm/issue/per-917), лист [PER-916](https://linear.app/anticnvm/issue/per-916), [PR #729](https://github.com/Solguficky/solguficky-hub/pull/729) слит. Снятие дерева после мержа — шаг скилла [proj-run-epic](../../../.skillshare/skills/proj/proj-run-epic/SKILL.md), команда `orca worktree rm --worktree path:<дерево>`. Внешнее ревью листа шло через Codex двумя проходами. Исполнитель — Claude Sonnet, его dispatch к этому моменту завершился (`succeeded`).
- **Наблюдение:** `orca worktree rm` дерева `per-916` ответил «is open in another program. Close that program and delete again» и вернул 1. Файлы дерева при этом удалились, а пустой каталог остался, и `git worktree list` показывает его `prunable`. Каталог держал процесс `node` с командой `app-server-broker.mjs serve … --cwd C:/Users/anticnvm/orca/workspaces/solguficky-hub/per-916`: это брокер Codex, поднятый для ревью в дереве листа и переживший исполнителя. Остановку процесса оркестратором отклонил классификатор auto mode. Деревья `per-906` и `per-914` того же эпика та же команда сняла без остатка.
- **Последствие:** дерево снято наполовину. Дочистка — остановить процесс, удалить каталог и `git worktree prune` — ушла владельцу отдельным пунктом сводки, хотя по правилу деревья снимаются в день мержа. Процесс брокера продолжал работать без исполнителя.
- **Адресат:** Скилл — шаг снятия дерева в `proj-run-epic`: перед `orca worktree rm` найти процессы, чей рабочий каталог лежит в дереве, а остановку чужого процесса передать владельцу одним вопросом вместе с мержем. Второй адресат — Скилл `proj-deliver-task`: исполнитель, который поднимал Codex на ревью, перед `worker_done` останавливает брокер своего дерева. Автоматическая проверка подошла бы, если снятие дерева станет рецептом: поиск процесса по `--cwd` не требует суждения.
- **Повторение:** первое наблюдение.
- **Следующий сигнал:** в другом дереве `orca worktree rm` или `git worktree remove` отказывает или оставляет каталог из-за процесса Codex или другого инструмента ревью с рабочим каталогом в дереве.
- **Статус:** наблюдение
