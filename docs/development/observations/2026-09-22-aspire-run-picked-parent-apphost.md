# 2026-09-22 — `aspire run` из рабочего дерева поднял AppHost основного клона

- **Контекст:** PER-212, дерево `.claude/worktrees/per-218-project-task-b7d2ac`, [PR #153](https://github.com/Solguficky/solguficky-hub/pull/153); команда `aspire run -- --profile notifications` из `infra/apphost` этого дерева; [local-development.md](../local-development.md), раздел про профили.
- **Наблюдение:** запуск собрал `..\..\..\..\..\infra\apphost\AppHost.csproj` — пять уровней вверх, то есть AppHost основного клона — и упал `Unknown topology profile 'notifications': no section 'Topology:Profiles:notifications'. Known profiles: hub, identity, infra, meetups`. Стек указал на `C:\Users\anticnvm\code\solguficky-hub\infra\apphost\Configuration\ProfileResolver.cs`, файл вне дерева. Причина в раскладке: рабочие деревья лежат в `.claude/worktrees/` внутри основного клона, поэтому поиск AppHost вверх по каталогам находит родительский раньше своего. Запуск с явным `aspire run --apphost infra/apphost/AppHost.csproj -- --profile notifications` поднял нужный граф, и `aspire list_apphosts` подтвердил путь внутри дерева.
- **Последствие:** отказ выглядит как ошибка в собственной правке `appsettings.json` — перечень известных профилей приходит из чужого файла и не содержит только что добавленного. Диагноз стоил отдельного круга чтения; при совпадении имён профилей отказа не было бы вовсе, и живой прогон молча подтвердил бы работу чужого графа.
- **Адресат:** Автоматическая проверка — рецепт в `justfile`, передающий `--apphost` явным путём: команда однозначна, суждения не требует и снимает сигнал на каждом следующем прогоне. Правило в `AGENTS.md` дешевле не выходит: оно занимает контекст каждой сессии, а выполняется всё равно командой.
- **Повторение:** первое наблюдение. Родственная запись 2026-09-18 «Разведка читает сгенерированный код в чужом рабочем дереве» — того же класса «в работу попал артефакт вне своего дерева», но там подагент читал чужой файл, а здесь инструмент сам ушёл вверх по дереву каталогов и собрал чужой проект.
- **Следующий сигнал:** команда, запущенная в рабочем дереве, читает или собирает файл основного клона, потому что ищет его вверх по дереву каталогов.
- **Статус:** наблюдение
