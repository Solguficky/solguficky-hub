# 2026-09-29 — Номер ADR свободен на develop, но занят открытым pull request

- **Контекст:** PER-318, [PR #270](https://github.com/Solguficky/solguficky-hub/pull/270), коммит `5f279c5`; шаг 10 скилла `proj-record-decision`, [check-document-numbers.sh](../../../tools/docs/check-document-numbers.sh).
- **Наблюдение:** перед открытием PR шаг 10 `proj-record-decision` велит взять «следующий свободный номер по `origin/develop` и уже пронумерованным файлам этой ветки». По `git ls-tree origin/develop docs/decisions/` последним был `ADR-055`, значит следующий — `ADR-056`. Но `ADR-056-service-calls-per-caller-token-and-closed-network.md` уже лежал в открытом PR ветки `feature/PER-265`. Это увидела только ручная сверка: `gh pr list` и `git diff --name-only origin/develop...origin/<ветка> -- docs/decisions/` по каждой открытой ветке. Документ получил `ADR-057`. `just check-document-numbers` на этом шаге был зелёным при любом из двух номеров: он читает рабочее дерево ветки, где второго `ADR-056` нет.
- **Последствие:** коллизия не случилась только благодаря ручной сверке вне процесса. Без неё два открытых PR несли бы один номер, и тот, что мержится вторым, узнал бы о нём по красной джобе `check-document-numbers` на merge ref уже после мержа первого — то есть после сдачи и с новым кругом переименований и правки ссылок. Правило из записи [2026-09-12](2026-09-12-document-number-taken-at-creation.md) ловит коллизию с принятым develop, но не с параллельной, ещё не принятой веткой.
- **Адресат:** Автоматическая проверка — `tools/docs/check-document-numbers.sh` либо отдельный рецепт, который сверяет номера ветки с номерами документов на `refs/remotes/origin/*`. Верхний адресат подходит: «номер этой ветки встречается в другой remote-ветке» проверяется командой без суждения. Второй адресат — шаг 10 `proj-record-decision`: он называет источником свободного номера только develop и файлы своей ветки.
- **Повторение:** первое наблюдение этого механизма. Запись 2026-09-12 того же класса «номер — распределённый счётчик без блокировки», но её правило и проверка смотрят на develop и merge ref, а открытые ветки видели только ручным обходом при её разборе.
- **Следующий сигнал:** PR, открытый с ADR или RFC, номер которого уже несёт другой открытый PR, либо переименование документа из-за такой пары.
- **Статус:** наблюдение
