# 2026-09-28 — Проба Codex читает файл диффа, который скилл велит класть вне рабочего дерева

- **Контекст:** PER-315, дерево `.claude/worktrees/per-315-project-task-9dffe0`, [PR #255](https://github.com/Solguficky/solguficky-hub/pull/255). Шаг 4 скилла [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md).
- **Наблюдение:** шаг 4 даёт два предписания, которые друг другу противоречат. Первое: файл диффа пиши «во временный каталог, а не в рабочее дерево». Второе: исполнителя другого семейства проверь вызовом, «который читает файл рабочего дерева — например, файл диффа». Агент выполнил оба дословно. Дифф лёг в scratchpad сессии, а проба `codex:codex-rescue` получила этот путь и вернула: «it is outside the filesystem's permitted workspace root». Проба шла в переднем окне и держала запуск осей около 5,5 минуты (`duration_ms: 324790`). После отказа fallback сработал сразу: ось корректности прошла на модели сессии, отчёт назвал «независимость не достигнута».
- **Последствие:** проба отказывает по построению, при исправной среде и доступном CLI. Поэтому она не отличает недоступный Codex от доступного, и ось корректности теряет другое семейство в любом прогоне, где скилл выполнен дословно. Правило из [записи об оси корректности](2026-09-22-correctness-axis-lost-its-other-family.md) заводилось, чтобы не тратить заходы на недоступного исполнителя. В нынешнем виде оно отсекает и доступного.
- **Адресат:** Скилл — `proj-review-change`, шаг 4. Проба и сама ось должны получать файл внутри корня, который видит Codex: либо проба читает любой отслеживаемый файл дерева, либо файл диффа для оси корректности кладётся в рабочее дерево под погашенный каталог, например `.work/`.
- **Повторение:** второй независимый случай того же механизма. Первый — PER-209, [PR #199](https://github.com/Solguficky/solguficky-hub/pull/199), 2026-09-25, второй случай [записи об оси корректности](2026-09-22-correctness-axis-lost-its-other-family.md): `codex:codex-rescue` не прочитал путь к файлу с диффом, потому что файл лежал вне корня рабочей области. Та запись переведена в правило, и правило перенесло в скилл сам источник отказа: пробу чтением файла диффа при диффе вне дерева. Поэтому случай заведён новой записью, а не дописан туда.
- **Следующий сигнал:** проба или ось на исполнителе другого семейства снова отказывает из-за пути вне корня рабочей области, а не из-за среды, лимита или таймаута.
- **Правило из двух случаев:** файл, который должен прочитать исполнитель другого семейства, лежит внутри рабочего дерева, в каталоге, погашенном `.gitignore`. Проба доступности читает этот же файл: тогда её зелёный значит, что ось сможет прочитать дифф, а красный — что исполнитель действительно недоступен.
- **Перенесено:** шаг 4 [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md): файл диффа лежит в `.work/review/` внутри дерева, и проба исполнителя другого семейства читает этот же файл. Правило принято владельцем 2026-09-28.
- **Статус:** переведено в правило
