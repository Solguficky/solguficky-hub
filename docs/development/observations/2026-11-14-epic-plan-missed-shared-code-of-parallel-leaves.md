# 2026-11-14 — План эпика назвал два листа независимыми, а общий для них каркас нашла только разведка листа

- **Контекст:** эпик [PER-679](https://linear.app/anticnvm/issue/per-679), план оркестратора согласован владельцем 13 ноября. Развилка D-1: [PER-683](https://linear.app/anticnvm/issue/per-683) (`/meetups`) и [PER-685](https://linear.app/anticnvm/issue/per-685) (`/lot`) после мержа PER-682 идут параллельно, `blockedBy` между ними нет. Шаг плана скилла [proj-run-epic](../../../.skillshare/skills/proj/proj-run-epic/SKILL.md).
- **Наблюдение:** на чекпоинте плана исполнитель PER-685 нашёл общий каркас команд чата сообщества. Он нужен и `/meetups`, и `/lot`: разбор команды группы, шёпот, `ResolveIdentity`, кадры ADR-078 п. 3. В постановке PER-683 каркас был заказан поимённо, в постановке PER-685 его не было, а план эпика пересечение не назвал. Вопрос ушёл владельцу (Q-4) с тремя вариантами: каждый лист пишет свой, каркас у PER-683, каркас у PER-685. Выбор B: каркас пишет PER-683, PER-685 делает лотовую часть и подключает `/lot` после мержа PER-683. План получил поправку.
- **Последствие:** лишний вопрос владельцу на чекпоинте. PER-685 из параллельного листа стал зависимым, его ветке понадобился merge `origin/develop` с #718 и подключение второй частью. Без вопроса два листа написали бы два каркаса, и конфликт разрешал бы второй мерж.
- **Адресат:** Скилл — шаг плана `proj-run-epic`. Для листьев, которые план ставит параллельно, план называет общий код, нужный обоим: модуль, каркас, реестр. Каждый такой кусок получает владельца-лист, а второй лист — порядок. Второй адресат — `proj-create-task` при декомпозиции. Автоматическая проверка не подходит: пересечение по смыслу видно только при чтении постановок и кода.
- **Повторение:** первое наблюдение этого сигнала. Родственные записи — [декомпозиция без серверной стороны вызова](2026-11-11-decomposition-missed-server-side-of-call.md): там кусок не достался ни одному листу, здесь он нужен двум. И [поломки из-за порядка мержа](2026-11-12-merge-order-regressions-found-only-by-pr-review.md). Адресат у всех трёх — шаг плана `proj-run-epic`.
- **Следующий сигнал:** в другом эпике исполнитель листа, который план поставил параллельно соседнему, на разведке или чекпоинте находит общий с соседом код, не названный в плане.
- **Статус:** наблюдение
