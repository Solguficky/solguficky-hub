# 2026-09-29 — Codex вернул нулевой код и вердикт «дефектов нет», не прочитав дифф

- **Контекст:** PER-409, ветка `feature/PER-409`, [PR #266](https://github.com/Solguficky/solguficky-hub/pull/266). Шаг 4 скилла [`proj-deliver-task`](../../../.skillshare/skills/proj/proj-deliver-task/SKILL.md): внешнее ревью `codex review --base origin/develop -c model="gpt-6-sol"` в фоне, запасной путь — OpenCode, если Codex «нет или он упал (лимит, авторизация)».
- **Наблюдение:** Codex четыре раза получил `exec_command failed: CreateProcess … helper_unknown_error: setup refresh had errors` и не смог запустить ни одной локальной команды, включая `git diff`. Дальше он ходил через `codex_apps/github.*` и закончил с кодом 0 и вердиктом «No actionable defects were found in the PR diff against the specified merge base, and CI passed». Ветки на GitHub в этот момент не было: ревью шло около 08:33–08:40, первый push — в 11:37. Вердикт относился к чужому состоянию, а оговорка, что локальный дифф не проверен, стояла в последней фразе отчёта. Агент распознал подмену по тексту и запустил запасной путь; OpenCode прочитал дифф и дал настоящую находку (`ReplicaBindings.LastFailure` после успешной привязки).
- **Последствие:** шаг 4 переключает на запасной путь только при падении Codex. Нулевой код с уверенным вердиктом под это условие не подпадает, и отчёт, прочитанный по коду возврата или по первой фразе, сошёл бы за состоявшееся ревью с нулём находок. Цена здесь — около 8 минут фонового прогона без результата; без ручного чтения — пропущенная находка.
- **Адресат:** Скилл — `proj-deliver-task`, шаг 4: признак «Codex не отработал» определяется по содержанию отчёта — прочитан ли локальный дифф, — а не по коду возврата. Автоматическая проверка выше не подходит: отличить вердикт по диффу от вердикта по GitHub сейчас можно только чтением отчёта. Хука нет: событие — текст вывода фонового процесса.
- **Повторение:** первое наблюдение этого сигнала. Тот же отказ среды Codex (`setup refresh had errors`) записан для шага внешнего ревью в записи 2026-09-29 «Внешнее ревью в контуре не отработало ни основным, ни запасным инструментом» (PER-373, в `develop`), но там Codex честно сообщил, что ревью не завершено, а сигнал записи — прерванный запасной путь. Здесь запасной путь сработал, а новое — ложный уверенный вердикт при нулевом коде.
- **Следующий сигнал:** в другой задаче внешний ревьюер завершается с кодом 0 и вердиктом о диффе, которого он не читал — локальные команды не запускались, либо вывод ссылается на PR или CI, которых на момент ревью нет.
- **Статус:** наблюдение
