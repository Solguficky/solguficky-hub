# 2026-09-30 — Установка nats-tester общая на все рабочие деревья

- **Контекст:** PER-411, дерево `orca/workspaces/solguficky-hub/per-411`, [PR #279](https://github.com/Solguficky/solguficky-hub/pull/279). Шаг 3 `proj-start-task`: `just tools` на свежем дереве; рецепт `nats-tester-tools` в `justfile` — `cd tools/nats-tester && python -m pip install -e .`.
- **Наблюдение:** `just tools` вернул 1 на последнем рецепте, `nats-tester-tools`. pip ставит editable-пакет в общий пользовательский site-packages Python, а там уже лежала установка того же пакета из дерева `per-394`. На её удалении pip упал с `OSError: [Errno 2] No such file or directory: …\Scripts\nats-tester.exe`, оставил битую запись `~ats-tester` и вышел с кодом 1. После этого `pip show nats-tester` по-прежнему показывает `Editable project location: …\per-394\tools\nats-tester`. На машине одна установка на все деревья, и CLI `nats-tester` в любом дереве исполняет код дерева, которое ставило его последним. В сессии отказ был записан как «окружение» без разбора.
- **Последствие:** гейту этого среза отказ не помешал: правка была только в `docs/`, а `nats-tester-check` в выборку `verify-changed` не попал. Дерево, которое правит `tools/nats-tester/`, запустит ручную проверку и гейт на чужом коде без единого предупреждения. Разбор такого расхождения начнётся с диффа, а не с установки. Свежее дерево вдобавок получает красный `just tools`, который читается как «окружение» и не чинится по правилу контура.
- **Адресат:** Автоматическая проверка — рецепт `nats-tester-tools` в `justfile`: изоляция установки на дерево, например venv внутри `tools/nats-tester/`, и вызовы `nats-tester-*` из него. Рецепт — команда без суждения, поэтому нижние адресаты не нужны.
- **Повторение:** второй независимый случай — 2026-10-18, PER-627, дерево `orca/workspaces/solguficky-hub/per-627-pr`, [PR #470](https://github.com/Solguficky/solguficky-hub/pull/470). `just tools` на свежем дереве снова вернул 1 на `nats-tester-tools` с той же `OSError: [Errno 2] No such file or directory: …\Scripts\nats-tester.exe`, а `pip show nats-tester` после этого показывал `Editable project location: …\per-483\tools\nats-tester` — установку из третьего дерева. Отказ снова записан как «окружение» без разбора; гейту он не помешал, потому что `tools/nats-tester/` срез не трогал.
- **Правило из двух случаев:** рецепт `nats-tester-tools` ставит пакет в окружение, изолированное на рабочее дерево, — venv внутри `tools/nats-tester/`, — и рецепты `nats-tester-*` вызывают CLI оттуда; общий пользовательский site-packages Python для editable-установки компонента не используется.
- **Следующий сигнал:** `just tools` или рецепт `nats-tester-*` в другом дереве снова падает на установке пакета, либо `pip show nats-tester` указывает не на текущее дерево, пока в нём идёт правка `tools/nats-tester/`.
- **Статус:** вынесено на обсуждение
