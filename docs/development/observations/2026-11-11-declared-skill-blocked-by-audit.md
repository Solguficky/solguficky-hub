# 2026-11-11 — Объявленный скилл не проходит audit skillshare, и первичная настройка дерева не завершается

- **Контекст:** дерево Orca `orca/workspaces/solguficky-hub/cachalot`, рецепт `just skillshare-install` поверх `tools/skillshare/install.sh`, запись `_aspire-skills` в `.skillshare/config.yaml` с источником `https://github.com/microsoft/aspire-skills.git`.
- **Наблюдение:** `just skillshare-install` поставил 19 записей из 20 и вышел с кодом 1. Группу `_aspire-skills` заблокировал собственный security audit skillshare двумя находками уровня CRITICAL «Output suppression directive»: `aspire-deployment/references/preflight.md:170` («do not tell the user it will deploy») и `aspire-orchestration/references/safety-guardrails.md:167` («do not tell the user the…»). По контексту обе строки запрещают вводить пользователя в заблуждение, а не прятать от него действия, то есть срабатывание ложное. Install вычеркнул запись из объявления, обёртка это поймала и напечатала `dropped: _aspire-skills` с советом «Restore it and retry». Совет повторить не помогает: тот же источник даст тот же отказ. Объявление восстановлено `git checkout`, скиллы `aspire-deployment` и `aspire-orchestration` в дереве так и не появились.
- **Последствие:** шаг первичной настройки из `AGENTS.md` на чистом дереве не завершается зелёным, и это видно только по выводу рецепта. Отказ по аудиту обёртка называет так же, как дрейф объявления, поэтому причина читается по логу skillshare выше, а совет повторить ведёт в ту же стену. Часть объявленных скиллов в дереве отсутствует молча для следующей сессии.
- **Адресат:** Автоматическая проверка — `tools/skillshare/install.sh`: отказ audit называется отдельной строкой с именем записи и находками и не сопровождается советом повторить. Само объявление — решение владельца: снять запись, ставить её с явным обходом аудита или закрепить версию источника без находок.
- **Повторение:** второй независимый случай. Первый — PER-99, 2026-09-12, запись [о молчаливых правках skillshare](2026-09-12-skillshare-silently-edits-tracked-files.md): там тот же audit заблокировал `aspire-orchestration` уровнем CRITICAL. Правило той записи закрыло молчаливую правку объявления, а сама блокировка осталась. Другая задача, другое дерево, другая сессия, отказ того же аудита на том же источнике два месяца спустя.
- **Следующий сигнал:** `just skillshare-install` на чистом дереве выходит с ненулевым кодом из-за отказа audit на записи, которая есть в объявлении.
- **Правило из двух случаев:** объявление `.skillshare/config.yaml` держит только записи, которые проходят audit skillshare, либо запись несёт явное и названное в объявлении исключение аудита. Признак выполнения правила — `just skillshare-install` на чистом дереве выходит с кодом 0. Область — объявление внешних скиллов и обёртка их установки.
- **Статус:** вынесено на обсуждение
