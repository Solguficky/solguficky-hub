# 2026-09-21 — Правило «снимай дерево в тот же день» есть, а деревья слитых PR живут неделю

- **Контекст:** сессия RFC-013, `git worktree list` в основном клоне и `gh pr list --state all`; правило в [AGENTS.md](../../../AGENTS.md) и [branching.md](../../standards/git/branching.md), введено [PR #99](https://github.com/Solguficky/solguficky-hub/pull/99) 2026-09-12.
- **Наблюдение:** из девяти рабочих деревьев рядом с основным клоном у шести pull request слит: `per-245-task-cb332e` ([PR #107](https://github.com/Solguficky/solguficky-hub/pull/107), 2026-09-13), `per-35-project-task-50606f` ([PR #110](https://github.com/Solguficky/solguficky-hub/pull/110), 2026-09-14, detached HEAD), `auction-notes-persistence-799430` ([PR #128](https://github.com/Solguficky/solguficky-hub/pull/128), 2026-09-20), `agent-execution-cost` ([PR #134](https://github.com/Solguficky/solguficky-hub/pull/134)), `telegram-test-contour` ([PR #132](https://github.com/Solguficky/solguficky-hub/pull/132)), `per-146-project-task-784e10` ([PR #135](https://github.com/Solguficky/solguficky-hub/pull/135), 2026-09-20). Ещё два, `exciting-wing-a2fe82` и `heuristic-shannon-b595ba`, стоят на ветках `claude/…`, у которых PR нет вовсе. Правило действует девять дней, и ни одна из сессий, сдавших эти PR, дерево не сняла: сдача заканчивается открытием PR, а merge происходит позже и в другой сессии, у которой этого дерева нет в контексте. Дерево `per-146-project-task-784e10` при этом уже переиспользовано под ветку `docs/accept-auction-domain-rfc`, так что имя каталога перестало называть задачу.
- **Последствие:** `git worktree list` перестал отвечать на вопрос «что в работе», а разведка следующей задачи рискует прочитать чужое дерево, как в записи от 2026-09-18.
- **Адресат:** Автоматическая проверка — рецепт `just check-worktrees` или скрипт в `tools/git-hooks/`: сопоставить `git worktree list` с состоянием PR по ветке через `gh` и напечатать деревья, чей PR слит или закрыт. Правило словами есть и поведения не изменило, потому что момент его применения, merge, наступает вне сессии, которая о дереве знает. Второй адресат — Скилл `proj-start-task`: запускать эту проверку при старте следующего контура, когда агент в сессии есть.
- **Повторение:** первое наблюдение. Запись от 2026-09-02 про признак stale-дерева описывает ошибку в критерии, а не невыполнение правила.
- **Следующий сигнал:** `git worktree list` в основном клоне показывает дерево, чей PR слит больше суток назад.
- **Статус:** наблюдение
