# 2026-10-07 — Проверки образа зелёные, а процесс в образе не стартует

- **Контекст:** PER-454, [PR #371](https://github.com/Solguficky/solguficky-hub/pull/371). Первый production-образ бота аукциона, `apps/auction-bot/Containerfile` по образцу бота хаба, рецепт `just auction-bot-image`.
- **Наблюдение:** рецепт вернул `IMAGE_EXIT=0`. Все три проверки `tools/image/` прошли: «No Bot API token in 18 files», «/app … holds no dev-only package and no TypeScript sources». Ручной `docker run --rm --read-only auction-bot:local`, сделанный по собственной инициативе, упал на старте: `ERR_MODULE_NOT_FOUND: Cannot find package 'zod' imported from /app/node_modules/@solguficky/auction-bot-ui/…`. Образ копировал общий пакет без его `node_modules`. У бота хаба `zod` объявлен прямо, поэтому та же схема сборки у него работала. Проверки смотрят, что лишнего в образе нет, но не что нужное есть, и сам процесс не запускают. После исправления тот же запуск отказал уже на конфигурации: `AUCTION_BOT_TOKEN is not set`.
- **Последствие:** без ручного запуска образ ушёл бы в GHCR и автовыкладкой на stage подом, который падает на старте. Причина нашлась бы по логу пода уже на стенде.
- **Адресат:** Автоматическая проверка — проверка в `tools/image/` и шаг `image-publish.yml`: образ запускается с пустым окружением, и успехом считается отказ процесса на своей конфигурации, а не на загрузке модулей. Фикстура доказывает, что проверка ловит образ с недостающей зависимостью.
- **Повторение:** первое наблюдение. Записи с образами в журнале — о базе по digest и памяти сборки, а не о запуске собранного образа.
- **Следующий сигнал:** образ с зелёными проверками `tools/image/` падает при первом запуске — локально, в CI или на stage — на причине, которую видно без внешних зависимостей: модуль, файл, права, точка входа.
- **Статус:** наблюдение
