# 2026-09-22 — Правило про обёртку install не покрывает установку одного скилла

- **Контекст:** PER-212, дерево `.claude/worktrees/per-218-project-task-b7d2ac`, [PR #153](https://github.com/Solguficky/solguficky-hub/pull/153); команды `skillshare install github.com/managedcode/dotnet-skills/catalog/Frameworks/Orleans/skills/orleans -p` и `skillshare install <тот же репозиторий>/agents/dotnet-orleans-specialist -p --kind agent`; раздел про скиллы в [AGENTS.md](../../AGENTS.md), обёртка `tools/skillshare/install.sh` и рецепт `just skillshare-install`.
- **Наблюдение:** адресный install одного скилла переписал объявление зависимостей до того, что сам только что обработал: в `.skillshare/config.yaml` из 17 записей осталось две — новая `orleans` и приблудная `orca-linear`, которой в проектном объявлении не было вовсе, — а `.metadata.json` потерял 279 строк из 304. Объявление восстановлено `git checkout` и дописано руками. Второй install, тот что ставил роль с `--kind agent`, усёк его повторно и молча отменил ремонт: `git status --short` показал ту же букву `M`, что и правка в одну строку, и сломанное состояние ушло в коммит. Обнаружено по строке `5 files changed, 136 insertions(+), 320 deletions(-)` в выводе самого `git commit`, исправлено `--amend`. Прямой прогон подтверждает, что `skillshare sync --all -p` объявление не трогает вовсе: после него `git status --short` пуст. Правило репозитория существует и требует запускать install через `just skillshare-install`, но обёртка ставит всё по `config.yaml` и URL не принимает, а соседний абзац того же `AGENTS.md` прямо предписывает для нового скилла `skillshare install <url>`.
- **Последствие:** регрессия общего объявления уехала в коммит задачи, к которой отношения не имеет, и выжила ремонт между двумя установками. Единственный признак — число удалённых строк: `git status` этот класс потери не отличает от однострочной правки, а `just verify` его не видит, потому что `check-frontmatter.sh` разбирает источники скиллов, а не объявление.
- **Адресат:** Автоматическая проверка — `tools/skillshare/install.sh`: обёртка принимает URL и закрывает собой путь установки одного скилла, а не только массовый. Второй адресат — `AGENTS.md`: сейчас два его абзаца дают взаимоисключающие указания, и агент, выполнивший второе, обходит защиту, введённую первым.
- **Повторение:** первое наблюдение этого сигнала. Запись 2026-09-12 «Команды skillshare молча правят отслеживаемые файлы» переведена в правило, и её правило породило ту самую обёртку; здесь сигнал другой — не «инструмент правит молча», а «введённая защита не покрывает штатный путь и отменяется на каждом следующем вызове».
- **Следующий сигнал:** объявление зависимостей `.skillshare/` теряет записи после команды skillshare, запущенной не через `just skillshare-install`, либо ремонт объявления отменяется следующей командой того же инструмента.
- **Статус:** наблюдение
