# 2026-10-05 — Вызовы WSL из харнесса ломались на путях и кавычках оболочки хоста

- **Контекст:** PER-237, [PR #356](https://github.com/Solguficky/solguficky-hub/pull/356). Claude Code на Windows вызывал `wsl.exe` из Bash (Git Bash) и PowerShell 5.1, чтобы запускать Ansible и `ssh` в WSL.
- **Наблюдение:** Git Bash переписал аргумент `/mnt/c/...` в `C:/Program Files/Git/mnt/c/...`, и скрипт не нашёлся. Из PowerShell 5.1 до WSL не доходили кавычки: удалённая команда развалилась на части (`dpkg: error: need an action option`, `python | grep …: command not found`). Строка `CHECK_EXIT=0` пришла при `failed=1` в логе Ansible. Надёжно сработала одна форма: скрипт-файл в scratchpad через Write, вызов `wsl.exe -d Ubuntu -- bash -l <путь /mnt/c/...>` из PowerShell, удалённые команды в отдельном файле и `ssh … 'bash -s' < файл`.
- **Последствие:** около пяти лишних вызовов. Хуже другое: один ложный `EXIT=0` на красном прогоне, который поймало только чтение лога.
- **Адресат:** Правило в `AGENTS.md`: поведение агента должно меняться до первого вызова WSL. Автоматическая проверка и хук не подходят: вызов составляет агент, а событие «аргумент переписан» харнессу не видно. Сигнал завязан на машину с Windows и WSL, поэтому до второго случая место правила может оказаться памятью агента, а не `AGENTS.md`.
- **Повторение:** первое наблюдение. WSL в журнале упомянут только в записи 2026-09-17 по другому поводу.
  Второй независимый случай — PER-371, [PR #363](https://github.com/Solguficky/solguficky-hub/pull/363), та же машина, другая сессия. Inline-команда из PowerShell 5.1 с Jinja-выражением упала разбором самой PowerShell (`Missing type name after '['`), до WSL не дойдя. Длинный inline-heredoc с Python-скриптом в Git Bash упал с `unexpected EOF while looking for matching`. Оба раза сработала та же форма — скрипт-файл через Write и `wsl.exe -d Ubuntu -- bash -l <путь /mnt/c/...>`. Новое в этом случае: файлы внутри WSL правились инструментами Write и Edit по пути `\\wsl.localhost\Ubuntu\...`, и кавычки хоста в правках не участвовали вовсе.
  Третий случай — PER-311, [PR #366](https://github.com/Solguficky/solguficky-hub/pull/366), 2026-10-06, та же машина, другая сессия. Больше 40 вызовов из PowerShell по правилу прошли без сбоев. Сводка после сжатия контекста сохранила форму `wsl.exe -d Ubuntu -- bash -l /mnt/c/...`, но потеряла «из PowerShell». Первый же вызов из Bash получил `C:/Program Files/Git/mnt/c/...: No such file or directory`. Новое в этом случае: из Git Bash форма работает с `MSYS_NO_PATHCONV=1` перед `wsl.exe` — четыре вызова подряд прошли. Цена — один лишний вызов.
  Четвёртый случай — PER-384, [PR #541](https://github.com/Solguficky/solguficky-hub/pull/541) и [ops#16](https://github.com/Solguficky/solguficky-ops/pull/16), 2026-10-22, та же машина, другая сессия. Сигнал другой, и бьёт он по самому правилу: правка инструментом Edit по пути `\\wsl.localhost\Ubuntu\...`, который правило советует, сняла бит исполнения с `bin/stage` и `tests/stage.sh` ops (100755 → 100644). Так случилось дважды за сессию. Тесты ops этого не видят: они запускают скрипты через `bash <файл>`. Поймали оси ревью спецификации и корректности. Бит вернули `chmod 755` внутри WSL отдельным коммитом (ops `91efa19`) и сверили по `git ls-files -s`. Цена — лишний круг ревью и коммит исправления. Для этого сигнала есть адресат выше `AGENTS.md`: автоматическая проверка в ops, тест, который сверяет режим отслеживаемых скриптов по `git ls-files -s`.
- **Следующий сигнал:** в другой сессии вызов `wsl.exe` из Bash или PowerShell снова теряет путь или кавычки, либо код возврата обёртки расходится с исходом команды внутри WSL, либо правка по `\\wsl.localhost` снова меняет режим файла.
- **Правило из двух случаев:** на Windows с WSL агент не передаёт команду в WSL строкой через оболочку хоста. Команда пишется скрипт-файлом и вызывается `wsl.exe -d <дистрибутив> -- bash -l <путь /mnt/c/...>` из PowerShell либо из Git Bash с `MSYS_NO_PATHCONV=1`, а файлы внутри WSL правятся по пути `\\wsl.localhost\<дистрибутив>\...`. Вердикт читается по строке кода возврата внутри скрипта.
- **Статус:** вынесено на обсуждение
