# 2026-10-05 — Шаг для ручного запуска владельцем упал на дефекте, который агент мог поймать сам

- **Контекст:** PER-237, [PR #356](https://github.com/Solguficky/solguficky-hub/pull/356). Шаг 7 [`proj-start-task`](../../../.skillshare/skills/proj/proj-start-task/SKILL.md): playbook в приватном ops-репозитории, боевые прогоны запускал владелец по командам агента.
- **Наблюдение:** свои пробные прогоны под root агент делал с `--skip-tags sshd,firewall` или по одному тегу. Теги `sshd` и `firewall` в режиме check до передачи владельцу не прошли ни разу. Пробный прогон владельца под `ops` упал дважды подряд. Сначала проверка доступа с `delegate_to: localhost` ждала `sudo` на ноутбуке: `ansible_become` из inventory перекрывает ключевое слово `become: false`. Затем шаг ufw упал на отсутствующем `/etc/default/ufw`: в режиме check пакет не ставится. После каждой правки агент прогонял те же теги под root в режиме check, и оба дефекта воспроизводились этой доступной ему проверкой.
- **Последствие:** два лишних круга с владельцем, каждый с прогоном, скриншотом и паролем `sudo`, посреди работы на живом хосте с открытой консолью.
- **Адресат:** Скилл — `proj-start-task`, шаг 7: шаг, который исполняет владелец, сначала проходит все проверки, доступные агенту. Автоматическая проверка не подходит: какие проверки доступны, зависит от среды и среза.
- **Повторение:** первое наблюдение. Родственная запись — [команда с заглушкой в угловых скобках](2026-10-05-manual-command-with-angle-placeholder.md): тот же класс, «ручной шаг владельца ломается по причине, которую агент мог поймать», но другой механизм, синтаксис заглушки, а не непрогнанная проверка. Независимым повтором она не засчитана.
- **Следующий сигнал:** в другой задаче команда, отданная владельцу на ручной запуск, падает на дефекте, который агент мог воспроизвести доступной ему проверкой до передачи.
- **Статус:** наблюдение
