# 2026-11-22 — `achievements-format-check` красный на CRLF-выкладке, хотя правка Elixir не касалась

- **Контекст:** эпик [PER-908](https://linear.app/anticnvm/issue/per-908), лист [PER-930](https://linear.app/anticnvm/issue/per-930) ([PR #741](https://github.com/Solguficky/solguficky-hub/pull/741)), дерево Orca на Windows с `core.autocrlf=true`. Правка `contracts/proto/**` поднимает в выборе `just verify-changed` и группу achievements. Рецепт `achievements-format-check` выполняет `mix format --check-formatted`.
- **Наблюдение:** локальный `just verify-changed` дал EXIT=1 на одном рецепте: `achievements-format-check` назвал неформатированным `apps/achievements/lib/achievements/rules/first_bid.ex`. Дерево выложило 82 файла `apps/achievements/**` в CRLF при LF в индексе (`git ls-files --eol`: `i/lf w/crlf`). Повтор рецепта дал тот же EXIT=1. Версия Elixir совпадала с закреплённой. Джоба `achievements` в CI на LF-выкладке зелёная. Лист засчитали «гейт не оценил изменение» с вердиктом по CI — решение оркестратора R-10 по прецеденту R-3.
- **Последствие:** локальный гейт листа, который Elixir не трогает, не может быть зелёным на Windows-дереве. Каждое изменение контракта на такой машине идёт через «гейт не оценил» и ожидание CI, а исполнителю нужен ответ оркестратора, чтобы не чинить среду.
- **Адресат:** Автоматическая проверка — строки `eol=lf` в [.gitattributes](../../../.gitattributes) для исходников, которые форматтер гейта сравнивает побайтно (`*.ex`, `*.exs`), рядом с правилами для Go, TypeScript и Scala.
- **Повторение:** тот же механизм, что в записи [о регенерации nats-tester на Windows](2026-09-30-nats-tester-regeneration-flags-all-domains-on-windows.md): `autocrlf=true` держит в рабочем дереве CRLF, а инструмент гейта ждёт LF. Там правило перенесено только для каталога `generated/` nats-tester. Здесь другой каталог, другая задача и другой инструмент.
- **Правило из двух случаев:** каждый тип файла, который инструмент гейта читает или пишет побайтно (генератор, форматтер), получает `text eol=lf` в `.gitattributes` в том же изменении, что вводит инструмент. Это правило для всего репозитория, а не строка для одного каталога.
- **Следующий сигнал:** на Windows-дереве с `core.autocrlf=true` рецепт гейта краснеет или помечает файлы изменёнными только из-за CRLF в рабочем дереве.
- **Статус:** вынесено на обсуждение
