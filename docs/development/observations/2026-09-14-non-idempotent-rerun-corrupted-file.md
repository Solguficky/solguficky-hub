# 2026-09-14 — Повторный запуск неидемпотентной правки после частичного отказа испортил файл

- **Контекст:** PER-245, rebase на `origin/develop`, разрешение конфликта в `docs/decisions/README.md`, команда `sed -i '65d;67d;69d' ... && sed -i 's|...|...|' ...`.
- **Наблюдение:** первый `sed -i` удалил три строки и завершился успешно, второй упал на разделителе `|`, встретившемся внутри выражения: `unknown option to 's'`. Оболочка показала только вторую ошибку, и она читалась как «команда не сработала». Повторный запуск той же команды применил удаление строк 65, 67 и 69 к уже изменённому файлу и снёс строку чужого `ADR-040` с develop вместе с пустой строкой перед заголовком раздела. Файл в этот момент находился в состоянии конфликта посреди rebase.
- **Последствие:** испорчен индекс решений ровно в тот момент, когда он разрешался; потеряна строка документа из чужой смерженной задачи. Восстановление — `git checkout --merge -- docs/decisions/README.md`, возвращающий конфликтную версию файла; правка переделана одним проходом `awk`. Ошибка заметна только потому, что результат перечитывался глазами: `git status` показывает такой файл как обычный конфликт.
- **Адресат:** Правило в `AGENTS.md`, раздел про работу с файлами: поведение нужно до открытия файла, суждения не требует и командой не проверяется — цепочку составляет агент. Верхние адресаты не подходят по той же причине, что и в соседней записи.
- **Повторение:** первое наблюдение. Соседняя запись про пайп — другой механизм: там шаг молча не выполнился, здесь выполнился наполовину.
- **Следующий сигнал:** файл, испорченный повторным запуском команды, часть которой уже отработала.
- **Статус:** наблюдение
