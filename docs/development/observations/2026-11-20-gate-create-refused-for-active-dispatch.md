# 2026-11-20 — `gate-create` на Task с работающим исполнителем отказал `task_not_startable`

- **Контекст:** эпик [PER-917](https://linear.app/anticnvm/issue/per-917), Orca 1.4.266: в начале эпика она обновилась с 1.4.262. Шаг 10 скилла [proj-run-epic](../../../.skillshare/skills/proj/proj-run-epic/SKILL.md): вопрос, который держит лист с заведённой Task, дополнительно получает `gate-create --task <task_id>`. Скилл называет это экспериментом, поведение которого пишется в журнал.
- **Наблюдение:** первый вопрос эпика пришёл от исполнителя [PER-906](https://linear.app/anticnvm/issue/per-906) через `ask`, на чекпоинте плана (Q-1, 16:42 по Москве, Task `task_431aaa1e6d14`, dispatch `ctx_7bda3493ad1b`). `gate-create` на эту Task вернул `task_not_startable`: при активном dispatch gate не ставится. Остальные шесть вопросов эпика оркестратор вёл без gate. Вопрос жил в `questions.md`, сводке на зонте и ответе `reply`.
- **Последствие:** эксперимент скилла на этой версии Orca не даёт gate ни на одном вопросе исполнителя, ведь такой вопрос всегда приходит от работающего dispatch. Шаг 10 предписывает вызов, который заведомо отказывает, а `gate-list` на каждом входе ничего не показывает. Вопрос не блокирует Task средствами Orca, и держит его только журнал оркестратора.
- **Адресат:** Скилл — шаг 10 `proj-run-epic`: результат эксперимента переводит `gate-create` либо в вопросы без активного dispatch, либо из шага совсем. Автоматическая проверка не подходит: отказ даёт Orca, а не репозиторий.
- **Повторение:** первое наблюдение. Записей журнала о `gate-create` нет.
- **Следующий сигнал:** в другом запуске эпика `gate-create` на Task с активным dispatch снова отказывает `task_not_startable`. Если новая версия Orca gate поставит, запись дополняется этим фактом.
- **Статус:** наблюдение
