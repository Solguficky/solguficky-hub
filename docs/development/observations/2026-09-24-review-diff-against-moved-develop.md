# 2026-09-24 — Дифф для осей ревью собран против ушедшего вперёд develop

- **Контекст:** PER-208, дерево `.claude/worktrees/per-208-project-task-ee3e01`, [PR #183](https://github.com/Solguficky/solguficky-hub/pull/183); шаг 4 скилла `proj-review-change` («Надёжный сбор — `git add -A`, затем `git diff --cached`»).
- **Наблюдение:** срез ещё не был закоммичен, и дифф для ролей собран командой `git diff --cached origin/develop` — индекс против вершины удалённой ветки, а не против merge-base. За время работы develop ушёл вперёд на [#180](https://github.com/Solguficky/solguficky-hub/pull/180), и его изменения попали в дифф с обратным знаком: вместо 14 файлов среза оси получили ещё два десятка чужих — скиллы, `AGENTS.md`, скрипты `tools/` и записи этого журнала. Оси стандартов и спецификации честно объявили главной находкой «откат принятых правил вне границ задачи». Размер файла диффа — 1326 строк против ожидаемых нескольких сотен — был виден до запуска осей, но скилл проверяет только, что файл непуст.
- **Последствие:** два прогона осей ушли впустую, а находки пришлось опровергать в основном треде через `git log HEAD..origin/develop`. Ось корректности шла на том же диффе и сама назвала причину, иначе расхождение могло бы уйти владельцу как находка ревью.
- **Адресат:** Скилл — `proj-review-change`, шаг 4: для незакоммиченного среза базой служит merge-base (`git diff --cached $(git merge-base origin/develop HEAD)`), а после первого коммита — три точки из шага 1; вместе с «файл непуст» проверяется, что список файлов диффа совпадает с `git diff --name-only` среза. Автоматическая проверка не подходит: сбор диффа — шаг последовательности, а не свойство кода.
- **Повторение:** второй независимый случай того же ухода `develop` в середине контура — [2026-09-25 «`buf breaking` в гейте сравнил схемы с `develop`, ушедшим вперёд во время работы»](2026-09-25-verify-breaking-check-against-moved-develop.md) (PER-339): там пострадал гейт, а не дифф ревью; правило из двух случаев записано в той записи. Родственная запись 2026-09-22 «Ось ревью объявила отсутствующей строку, которая в диффе есть» — того же класса «вывод оси расходится с деревом», но там ошиблась ось на верном диффе, здесь оси верно прочитали неверный.
- **Следующий сигнал:** файл диффа, переданный осям ревью, содержит файлы, которых нет в `git diff --name-only $(git merge-base origin/develop HEAD)` среза.
- **Перенесено:** шаги 1 и 4 [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md): сверка базы перед диффом, дифф незакоммиченного среза от merge-base и сверка списка файлов диффа с `git diff --cached --name-only` до запуска осей. Правило общее с [записью о гейте](2026-09-25-verify-breaking-check-against-moved-develop.md), принято владельцем 2026-09-25.
