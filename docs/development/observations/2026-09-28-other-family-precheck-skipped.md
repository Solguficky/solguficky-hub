# 2026-09-28 — Проверка исполнителя другого семейства до ревью пропущена, хотя правило уже в скилле

- **Контекст:** PER-400, ветка `feature/PER-400`, [PR #257](https://github.com/Solguficky/solguficky-hub/pull/257); шаг 4 [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md), абзац «Исполнителя другого семейства для оси корректности проверь до запуска осей».
- **Наблюдение:** правило перенесено в скилл из записи [об оси корректности без другого семейства](2026-09-22-correctness-axis-lost-its-other-family.md) и требует до запуска осей один read-only вызов исполнителя, который читает файл рабочего дерева. Агент этого вызова не сделал и отдал ось `codex:codex-rescue` сразу вместе с двумя другими осями — дважды, до и после перезапуска приложения. Второй заход через три минуты вернул отказ среды `helper_unknown_error: setup refresh had errors` без единой находки. Fallback на модель сессии затем сработал по правилу: сразу, без повторных заходов, со строкой «независимость не достигнута».
- **Последствие:** около трёх минут ожидания и лишний запуск ревью на исполнителе, отказ которого распознала бы проверка до осей. Ущерба самому ревью нет: ось на модели сессии нашла настоящую находку. Правило в тексте скилла есть, но поведение при запуске осей не изменило.
- **Адресат:** Скилл — `proj-review-change`, шаг 4: проверка исполнителя вынесена отдельным пронумерованным шагом до сборки промптов осей, а её результат — обязательной строкой отчёта, без которой раздел «Корректность» не собирается. Автоматическая проверка и хук не подходят: вызов подагента составляет агент, и события для хука у него нет.
- **Повторение:** второй независимый случай. Первый — PER-365, [PR #231](https://github.com/Solguficky/solguficky-hub/pull/231), 2026-09-26: проверку до осей агент тоже пропустил и отдал ось Codex сразу; он записан третьим случаем в [исходной записи](2026-09-22-correctness-axis-lost-its-other-family.md), где предметом был медленный вызов, а не пропуск шага.
- **Следующий сигнал:** ось корректности снова отдаётся исполнителю другого семейства без предшествующего read-only вызова.
- **Правило из двух случаев:** проверка исполнителя другого семейства — отдельный шаг скилла перед запуском осей с обязательной строкой в отчёте ревью: «исполнитель проверен: ответил / отказал — причина». Отсутствие строки делает отчёт ревью неполным.
- **Статус:** вынесено на обсуждение
