# 2026-11-11 — Исполнители листов эпика работали на модели из настройки Orca, а не на модели уровня реализации

- **Контекст:** эпик [PER-740](https://linear.app/anticnvm/issue/per-740), Orca Run `run_f08f89faae7b`, шаг 5 скилла [proj-run-epic](../../../.skillshare/skills/proj/proj-run-epic/SKILL.md): `worker-start --task <task_id> --worktree path:<дерево> --agent claude` без `--model`. Таблица уровней — [agent-execution-cost.md](../agent-execution-cost.md).
- **Наблюдение:** `orca orchestration worker-list --run run_f08f89faae7b` показал у обоих исполнителей листов `agent=claude/claude-sonnet-5-5`. Сессия оркестратора шла на Opus 5.5. Таблица уровней относит реализацию к дорогому уровню, который наследует модель сессии. Скилл модель не передаёт, и Orca взяла её из настройки пользователя для новых вкладок агента. Оркестратор заметил это только при разборе состояния после эскалаций, когда листы уже сдавали работу. Ось логической корректности исполнитель PER-743 тоже провёл на Sonnet 5.5 с пометкой «независимость не достигнута».
- **Последствие:** реализация и ось корректности двух листов прошли на среднем уровне, хотя норматив ставит их на дорогой. Об этом не знали ни владелец при согласовании плана, ни сам оркестратор при старте. Отчёт исполнителя называет модель только в строке оси корректности.
- **Адресат:** Скилл — шаг 5 `proj-run-epic`: `worker-start` передаёт `--model` по строке «реализация» таблицы уровней, а строка `started` журнала записывает модель из квитанции или `worker-list`.
- **Повторение:** первое наблюдение. Записи [о пустом дешёвом пуле](2026-09-21-cheap-routing-pool-was-empty.md) и [об оси без другого семейства](2026-09-22-correctness-axis-lost-its-other-family.md) описывают подмену уровня при отказе пула. Здесь пул был доступен, а уровень молча задала настройка среды.
- **Следующий сигнал:** `worker-list` или квитанция `worker-start` в другом запуске эпика показывает у исполнителя листа модель ниже уровня реализации, а постановка или вызов её не задавали.
- **Статус:** наблюдение
