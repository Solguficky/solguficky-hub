# 2026-09-28 — Проба Codex через `codex exec` ждала stdin и сошла за недоступность

- **Контекст:** PER-238, дерево `.claude/worktrees/per-238-task-6994b6`, [PR #259](https://github.com/Solguficky/solguficky-hub/pull/259). Шаг 4 скилла [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md), проба исполнителя другого семейства перед осью корректности.
- **Наблюдение:** шаг 4 требует «один read-only вызов, который читает файл рабочего дерева», но формы вызова не называет. Агент вызвал Codex CLI напрямую через Bash: `timeout 90 codex exec --sandbox read-only "Print only the first line of the file …"`. stdin у вызова остался открытым. CLI напечатал «Reading additional input from stdin...» и ждал до таймаута. По правилу шага 4 агент засчитал отказ и сразу пустил ось корректности на модели сессии с пометкой «независимость не достигнута». Файл диффа при этом лежал в scratchpad вне дерева: правило `.work/review/` пришло в дерево с PER-315 уже после пробы. Так что проба отказала бы и по пути, но фактически её остановил stdin.
- **Последствие:** 90 секунд на пробе, и ось корректности потеряла другое семейство. Отказ неотличим от недоступного Codex, хотя CLI был установлен и отвечал: проба проверила форму вызова, а не исполнителя.
- **Адресат:** Скилл — `proj-review-change`, шаг 4: назвать форму пробы — `codex:codex-rescue` либо `codex exec … </dev/null`. Автоматическая проверка и хук не подходят: вызов составляет агент в сессии, и события «stdin не закрыт» у харнесса нет.
- **Повторение:** первое для Codex. Тот же механизм описан для omp в [omp.md](../omp.md): фаза `readPipedInput` требует перенаправить stdin. Родственная запись [о пробе Codex вне корня рабочей области](2026-09-28-codex-probe-reads-diff-outside-worktree.md) — другой механизм: там отказ давал путь к файлу, а не открытый stdin.
- **Следующий сигнал:** вызов CLI исполнителя другого семейства из Bash висит на чтении stdin либо снимается таймаутом без ответа, и отказ засчитан как недоступность исполнителя.
- **Статус:** наблюдение
