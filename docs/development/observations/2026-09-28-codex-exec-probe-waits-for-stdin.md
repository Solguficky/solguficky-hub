# 2026-09-28 — Проба Codex через `codex exec` ждала stdin и сошла за недоступность

- **Контекст:** PER-238, дерево `.claude/worktrees/per-238-task-6994b6`, [PR #259](https://github.com/Solguficky/solguficky-hub/pull/259). Шаг 4 скилла [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md), проба исполнителя другого семейства перед осью корректности.
- **Наблюдение:** шаг 4 требует «один read-only вызов, который читает файл рабочего дерева», но формы вызова не называет. Агент вызвал Codex CLI напрямую через Bash: `timeout 90 codex exec --sandbox read-only "Print only the first line of the file …"`. stdin у вызова остался открытым. CLI напечатал «Reading additional input from stdin...» и ждал до таймаута. По правилу шага 4 агент засчитал отказ и сразу пустил ось корректности на модели сессии с пометкой «независимость не достигнута». Файл диффа при этом лежал в scratchpad вне дерева: правило `.work/review/` пришло в дерево с PER-315 уже после пробы. Так что проба отказала бы и по пути, но фактически её остановил stdin.
- **Последствие:** 90 секунд на пробе, и ось корректности потеряла другое семейство. Отказ неотличим от недоступного Codex, хотя CLI был установлен и отвечал: проба проверила форму вызова, а не исполнителя.
- **Адресат:** Скилл — `proj-review-change`, шаг 4: назвать форму пробы — `codex:codex-rescue` либо `codex exec … </dev/null`. Автоматическая проверка и хук не подходят: вызов составляет агент в сессии, и события «stdin не закрыт» у харнесса нет.
- **Повторение:** первое для Codex. Тот же механизм описан для omp в [omp.md](../omp.md): фаза `readPipedInput` требует перенаправить stdin. Родственная запись [о пробе Codex вне корня рабочей области](2026-09-28-codex-probe-reads-diff-outside-worktree.md) — другой механизм: там отказ давал путь к файлу, а не открытый stdin.
- **Следующий сигнал:** вызов CLI исполнителя другого семейства из Bash висит на чтении stdin либо снимается таймаутом без ответа, и отказ засчитан как недоступность исполнителя.
- **Второй случай (2026-09-30):** PER-423, [PR #284](https://github.com/Solguficky/solguficky-hub/pull/284). Проба `codex exec -s read-only …` в обычном Bash прошла и вернула первую строку диффа. Сама ось корректности тем же `codex exec`, но запущенная в Bash с `run_in_background`, напечатала «Reading additional input from stdin...» и ждала, пока агент не снял её. Перезапуск с `< /dev/null` оборвался вместе с перезапуском сессии (exit -1; причина не установлена и к сигналу не относится), и ось ушла на модель сессии с пометкой «независимость не достигнута». Зелёная проба, выходит, не доказывает, что вызов оси не зависнет: форма вызова у них разная.
- **Третий случай (2026-11-13):** [PER-749](https://linear.app/anticnvm/issue/per-749), [PR #714](https://github.com/Solguficky/solguficky-hub/pull/714), Orca worker эпика PER-740. Исполнитель запустил `codex exec` в фоне без `</dev/null`, и вызов ждал stdin. Исполнитель сам назвал это кандидатом рефлексии в `worker_done`. Ось корректности и внешнее ревью на Codex в итоге прошли. Правило записи к этому дню в `proj-review-change` не перенесено, и третий исполнитель снова наступил на ту же форму вызова.
- **Четвёртый случай (2026-11-13):** [PER-682](https://linear.app/anticnvm/issue/per-682), [PR #717](https://github.com/Solguficky/solguficky-hub/pull/717), Orca worker эпика PER-679. Проба `codex exec --sandbox read-only …` на переднем плане прошла и прочитала файл диффа. Ось корректности и внешнее ревью исполнитель запустил тем же `codex exec`, но в Bash с `run_in_background` и без `< /dev/null`. Обе проходки с 22:51 до 23:08 висели на «Reading additional input from stdin...». Исполнитель заметил это, только когда заглянул в файлы вывода, снял обе задачи и перезапустил с `< /dev/null`; обе отработали за несколько минут. Рисунок второго случая повторился: зелёная проба не доказывает, что вызов оси не зависнет. Около 17 минут ревью потеряно, правило в скилл по-прежнему не перенесено.
- **Правило из двух случаев:** `proj-review-change`, шаг 4, называет форму вызова исполнителя другого семейства из Bash — и для пробы, и для самой оси — с закрытым stdin: `codex exec … < /dev/null`.
- **Статус:** вынесено на обсуждение
