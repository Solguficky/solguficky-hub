# 2026-09-27 — Живой прогон считал записи по консольному логу, а не по Structured logs

- **Контекст:** PER-9, живой прогон 2026-09-27, [PR #245](https://github.com/Solguficky/solguficky-hub/pull/245); подсчёт доставок бота командой `aspire logs telegram-bot`; [local-development.md](../local-development.md), раздел «Сквозной идентификатор в логах».
- **Наблюдение:** чтобы проверить критерий «не теряет и не удваивает уведомления», агент считал записи `notification delivered` через `aspire logs telegram-bot | tr -d '\n' | grep`. Первый подсчёт дал 2, следующий — 0 при тех же доставках. На 0 ушёл цикл опроса на 73 секунды и ещё около шести вызовов с разными регулярными выражениями: они теряли разное число записей (3 записи, затем 0 строк вывода). Только разбор `json.raw_decode` после склейки собрал 65 записей, из них 3 доставки. Причина — форма вывода `aspire logs`: длинная JSON-строка переносится с префиксом ресурса и ANSI-кодами, и границы записей перестают совпадать со строками. Журнал прогона записал ложную причину: «после рестартов соседей». При этом раздел «Сквозной идентификатор в логах» уже называет канал для такого поиска: бот шлёт логи по OTLP в Structured logs, и фильтр по полю работает там. Через `aspire otel logs` и Aspire MCP этот канал был доступен в сессии.
- **Последствие:** около десяти вызовов и полторы минуты ожидания посреди прогона, пока владелец ждал ответа; ложный ноль доставок и неверная причина в журнале прогона. Вывод о доставке держался на клиенте владельца, а не на логе.
- **Адресат:** Правило в `AGENTS.md` — навигация до первого вызова: машинный подсчёт и поиск записей в живом прогоне идут по Structured logs (`aspire otel logs`, Aspire MCP), а консольный `aspire logs` для разбора не используется. Автоматическая проверка не подходит: сигнал про выбор канала, а не про результат, который проверяется командой. Руководство канал называет, но агент дошёл до него только после неверного счёта.
- **Повторение:** первое наблюдение.
- **Следующий сигнал:** в другой сессии счёт или поиск записей сервиса по консольному выводу `aspire logs` даёт число, которое расходится с Structured logs или с наблюдаемым исходом.
- **Статус:** наблюдение
