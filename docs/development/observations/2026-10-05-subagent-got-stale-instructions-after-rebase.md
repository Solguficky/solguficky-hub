# 2026-10-05 — Подагент получил файл инструкций в снимке с маркерами конфликта

- **Контекст:** PER-319, [PR #350](https://github.com/Solguficky/solguficky-hub/pull/350); перенос ветки на свежий `develop` с конфликтом в корневом `AGENTS.md`; оси ревью [`proj-review-change`](../../../.skillshare/skills/proj/proj-review-change/SKILL.md), шаг 4.
- **Наблюдение:** посреди rebase харнесс подгрузил корневой `AGENTS.md` в контекст с маркерами `<<<<<<< HEAD … >>>>>>> 909998e1`. Конфликт разрешили и закоммитили через минуту, но после сжатия контекста файл инструкций пришёл в той же устаревшей форме ещё раз. Ось «стандарты», запущенная после этого, дала жёсткую находку: «дифф убирает уже слитый текст PER-292 про закрытие лотов по дедлайну». Текст был на месте: `git show HEAD:AGENTS.md` нашёл обе фразы, а дифф строки состоял только из добавлений. Ось сама написала, что в контексте сессии файл был с маркерами. Подагент рефлексии, запущенный часом позже, увидел тот же снимок в своём контексте, хотя на диске и в `HEAD` маркеров уже не было. Механизм у харнесса не установлен.
- **Последствие:** находку пришлось опровергать сверкой с `HEAD`. Правка по ней вернула бы в абзац текст, который там уже есть, — дубль в карте репозитория.
- **Адресат:** Скилл — `proj-review-change`, шаг 4: если в сессии был rebase или слияние с конфликтом в файле инструкций (`AGENTS.md`, `CLAUDE.md`), промпт осей требует сверять содержимое файлов с диском или с `git show HEAD:<файл>`, а не с инструкциями в контексте. Верхние адресаты не подходят: устаревший снимок в контексте подагента командой не проверить, события для хука нет.
- **Повторение:** первое наблюдение. Родственная запись [2026-09-22](2026-09-22-review-claimed-absent-existing-line.md) того же класса: вывод оси расходится с деревом. Механизм другой: там ось не нашла строку, которая есть в диффе, здесь ось читала файл не из дерева, а из устаревшего снимка в контексте.
- **Следующий сигнал:** подагент или основной тред цитирует файл инструкций с маркерами конфликта либо в форме, которой нет ни на диске, ни в `HEAD`.
- **Статус:** наблюдение
