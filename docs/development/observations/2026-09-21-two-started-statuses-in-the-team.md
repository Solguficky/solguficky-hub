# 2026-09-21 — Захват требует started-статуса, а started-статусов в команде два

- **Контекст:** PER-200, захват задачи, `list_issue_statuses` команды Personal; [agent-execution-loop.md](../agent-execution-loop.md), раздел «Захват задачи».
- **Наблюдение:** правило захвата говорит «переводит задачу в started-статус», не называя, какой именно. В команде Personal started-статусов два: `In Progress` и `In Review`. Выбор сделан по смыслу названия — `In Progress`. Тот же документ называет появление второго started-статуса наблюдаемым признаком пересмотра носителя записи о захвате: «в наборе статусов появился второй started-статус — „перевести в started“ перестало быть однозначным».
- **Последствие:** запись о захвате недетерминирована между средами и сессиями. Исполнитель, выбравший `In Review`, пометит взятую задачу как находящуюся на ревью до появления pull request: занятость при этом читается верно — у обоих статусов тип `started`, — а стадия читается неверно, потому что pull request ещё нет.
- **Адресат:** Норматив — [agent-execution-loop.md](../agent-execution-loop.md), раздел «Захват задачи»: назвать статус захвата по имени либо сказать, как выбирать между started-статусами. Скилл не подходит: правило действует на любую среду, а не только на ту, где разложены скиллы.
- **Повторение:** первое наблюдение.
- **Следующий сигнал:** задача помечена при захвате не тем started-статусом, в который переводит её автоматика Linear по связанному pull request, либо две сессии пометили захват разными started-статусами.
- **Статус:** наблюдение
