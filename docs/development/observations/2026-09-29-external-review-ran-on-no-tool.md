# 2026-09-29 — Внешнее ревью в контуре не отработало ни основным, ни запасным инструментом

- **Контекст:** PER-373, ветка `feature/PER-373`, [PR #264](https://github.com/Solguficky/solguficky-hub/pull/264). Шаг 4 скилла [`proj-deliver-task`](../../../.skillshare/skills/proj/proj-deliver-task/SKILL.md): внешнее ревью моделью другого семейства параллельно осям `proj-review-change`, введённое [PR #262](https://github.com/Solguficky/solguficky-hub/pull/262).
- **Наблюдение:** оба CLI были в PATH. Основной путь `codex review --base origin/develop -c model="gpt-6-sol"` отработал в фоне и на каждой попытке выполнить команду получал `exec_command failed: CreateProcess … helper_unknown_error: setup refresh had errors`. Итог Codex: «The review could not be completed», находок нет. Запасной путь `opencode run -m openai/gpt-6-sol --agent plan` прочитал дифф и соседний код и прогнал `go test ./...`. Затем он полез в кеш модулей Go (`GOMODCACHE`, вне рабочего дерева) и получил `permission requested: external_directory … auto-rejecting`, после чего прервался: «Tool execution interrupted», без вердикта. В отчёте осталась строка «внешнее ревью не шло» с причинами, как требует шаг.
- **Последствие:** шаг внешнего ревью в первом же контуре после введения не дал ни одной находки. Оба прогона заняли время в фоне без результата. Отказ OpenCode не про доступность: инструмент работал и разбирал дифф, но для Go-кода ревьюеру нужен исходник зависимостей вне дерева, а неинтерактивный запуск такой доступ отклоняет. Поэтому запасной путь отказывает по построению на любом диффе, где ревьюер захочет проверить API библиотеки.
- **Адресат:** Скилл — `proj-deliver-task`, шаг 4: форма вызова запасного пути либо заранее разрешает чтение кеша модулей, либо велит не ходить за пределы дерева. Сам доступ, вероятно, живёт в ключе `permission` файла `opencode.jsonc`: его генерация rulesync не трогает (AGENTS.md, «Стандарты и локальные правила»). Отказ Codex с `setup refresh had errors` — механизм среды, уже описанный для оси корректности, и сюда он входит только как причина, по которой дошло до запасного пути.
- **Повторение:** первое наблюдение для шага внешнего ревью. Тот же отказ среды Codex (`helper_unknown_error: setup refresh had errors`) записан для оси корректности в [записи об оси без другого семейства](2026-09-22-correctness-axis-lost-its-other-family.md) и в [записи о пропущенной пробе](2026-09-28-other-family-precheck-skipped.md). Там предмет — порядок запуска оси, а не шаг внешнего ревью, поэтому случай заведён своей записью. Отказ OpenCode на `external_directory` встречается впервые. Второй случай — PER-297, дерево `.claude/worktrees/per-253-task-48ed2f`, [PR #267](https://github.com/Solguficky/solguficky-hub/pull/267), 2026-09-29 — повторяет отказ Codex и показывает, что он не фатален. `codex review` тем же вызовом шесть раз получил `setup refresh had errors`, обошёл его через MCP `node_repl` и GitHub MCP и примерно через 14 минут записал в лог находку [P2] про переполнение `Long` в `Money.scala:17`. Основной тред, видя в логе только ошибки и вызовы `node_repl`, счёл ревью упавшим, остановил фоновую задачу `TaskStop` и ушёл на запасной путь. `TaskStop` процесс на Windows не завершил: находка легла в лог через четыре минуты после остановки, и её никто не прочитал. Отчёт владельцу, тело PR и комментарий в Linear сказали «Codex не отработал»; поправку внесли только после рефлексии. Запасной путь OpenCode на этот раз отработал без отказов `external_directory` — дифф был на Scala, за кешем модулей ревьюер не ходил. Третий случай — PER-411, дерево `orca/workspaces/solguficky-hub/per-411`, [PR #279](https://github.com/Solguficky/solguficky-hub/pull/279), 2026-09-30. `codex review` на каждом `exec_command` получил тот же `setup refresh had errors` и закончил честным итогом «I could not review the patch» с кодом 0; исход прочитан по завершению процесса, как требует правило ниже. Запасной `opencode run -m openai/gpt-6-sol --agent plan` отработал без отказов `external_directory` — дифф был документальным — и нашёл две настоящие находки в ADR-057, обе исправлены до PR. После этого владелец попросил сделать OpenCode основным путём, а Codex запасным; правка скилла идёт отдельным решением. Там же выяснилось, что модель `gpt-6-sol` зашита строкой в скилле и нормативе контура, а `opencode models` уже показывает `openai/gpt-6.1-sol`.
- **Правило из двух случаев:** исход внешнего ревью читается по завершению процесса и его итоговому выводу, а не по ошибкам инструментов в промежуточном логе: `setup refresh had errors` в одном случае кончился «could not be completed», в другом — находкой. Остановленный вызов проверяется на завершение процесса, и его лог перечитывается перед отчётом; «внешнее ревью не шло» пишется только по итоговому выводу.
- **Следующий сигнал:** запасной путь внешнего ревью снова прерывается на отказе доступа за пределы рабочего дерева либо шаг внешнего ревью снова заканчивается строкой «внешнее ревью не шло» при установленных CLI.
- **Статус:** вынесено на обсуждение
