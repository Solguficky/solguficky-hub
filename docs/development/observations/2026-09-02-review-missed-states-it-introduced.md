- **Контекст:** PER-96, [PR #48](https://github.com/Solguficky/solguficky-hub/pull/48), коммиты `510131a` и `7d09dc1`. Второй случай — PER-144, [PR #112](https://github.com/Solguficky/solguficky-hub/pull/112), коммиты `cfb451a` и `b3bd1c5`.
- **Наблюдение:** `proj-review-change` прошёл изменение тремя осями и находок такого рода не дал. После открытия PR внешние ревьюеры нашли три дефекта, все — в состояниях, которых до этого изменения не существовало. Изменение вводило draft PR как носитель чекпоинта, то есть состояние «на ветке уже есть PR, но работа не сдана»; шаг сдачи после него упирался в `a pull request for branch ... already exists`, а запрет открывать PR на красном гейте смыкался с требованием фиксировать остановку и терял работу фонового запуска. Третья находка того же рода: признак stale-дерева «нет ни коммитов, ни правок» выполняется сразу после `git worktree add`.

  Повторилось на PER-144. Изменение вводило восемь правил торгов псевдокодом; `proj-review-change` прошёл его тремя осями и нашёл шесть дефектов. После этого независимое ревью Codex нашло ещё пять, и все пять — в ветках правил, которые ввёл сам документ: равные максимумы прокси-лимитов, устаревший лимит лидера после его же ручной ставки, порог приёма ставки при объявленном ask, цена за последним ценовым порогом, повтор команды после именованного отказа. CodeRabbit добавил шестое того же рода — конфигурация лота, которую правила читали, отсутствовала в восстанавливаемом состоянии.
- **Последствие:** два коммита-фикса уже после сдачи. Ось корректности при этом сработала — она нашла соседний дефект в том же месте, — но искала недостающее, а не последствия добавленного. На PER-144 — ещё два коммита-фикса после открытия PR; ни один из шести дефектов второго круга не был найден своими осями, хотя каждый выводится прогоном по веткам правила, которое ввёл сам документ.

- **Повторение:** второе независимое подтверждение — PER-96 (2026-09-02) и PER-144 (2026-09-14), разные задачи и сессии.
- **Правило, которое получается из двух случаев:** ось корректности `proj-review-change` перечисляет состояния и ветки, которые вводит само изменение, и проходит по каждой отдельно — вместо того чтобы искать недостающее в состояниях, существовавших до него.
