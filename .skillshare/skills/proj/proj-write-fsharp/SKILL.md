# Писать F#-код

Порядок работы ниже, форма кода и примеры на каждое правило — в нормативе [languages/fsharp.md](../../../docs/standards/languages/fsharp.md). Открой его вместе с этим skill: примеры живут там и здесь не повторяются. Устройство приложения из срезов ведёт `proj-write-fsharp-vsa`, тесты — `proj-test-fsharp`, состав полей лога — [logging.md](../../../docs/standards/observability/logging.md). Здесь только язык.

## 1. Прочитай конфигурацию

Ближайший `AGENTS.md`, `.fsproj`, `Directory.Build.props`, `Directory.Packages.props` и настроенные build, test, lint и format commands. Существующая конфигурация — источник правды: следуй её target framework, версиям пакетов, formatter и analyzers. Отсутствующий в ней инструмент по памяти не вводится.

Конфигурации ещё нет — остановись и спроси владельца. Выбор стека принадлежит ему; принятое по F# лежит в [ADR-025](../../../docs/decisions/ADR-025-meetups-fsharp-stack.md).

Сгенерированный C# контрактов рождается `dotnet build` контрактного проекта и меняется только правкой `.proto` ([стандарт](../../../docs/standards/contracts/protobuf.md#кодогенерация-net)). Сам `.proto` меняется через `proj-change-contract`.

## 2. Граница данных

- Найди место, где nullable C#, Protobuf message, строка таблицы или внешний ответ становятся F#-типом. Это и есть trusted boundary: снаружи данные недоверенные, внутри DTO и повторные проверки примитивов не протаскиваются.
- Отображение проверяет обязательность, диапазоны и неизвестные варианты до вызова домена. Неизвестный вариант enum — явный отказ: `protoc` даёт вариант `0` на любое нераспознанное число, и ветка по умолчанию превратит чужую версию схемы в тихо неверные данные.
- Успешно отображённое значение внутри workflow заново не проверяется.

## 3. Типы

- Взаимоисключающие состояния — discriminated union, отсутствие — `option`. Набор связанных `bool`, nullable и optional-полей заменяй вариантами.
- Значение с инвариантом получает private single-case union и модуль-компаньон: `create`, возвращающий `Result`, и `value` наружу. Проверка живёт в `create` и больше нигде.
- Pattern match по закрытому набору оставляй исчерпывающим. Catch-all в решающей ветке скрывает новый вариант от компилятора.
- Публичная сигнатура показывает допустимые входы, результаты и эффекты. Представление типа, собираемого в недопустимом состоянии, скрывается.

## 4. Чистота и зависимости

- Доменная функция детерминирована: часы, UUID, random, environment, сеть и база приходят значениями из императивной оболочки.
- Зависимости выражаются минимальными функциями или record of functions рядом с их потребителем. `IServiceProvider`, container lookup и scoped service внутрь workflow не проходят; создание и disposal — в composition root или адаптере.
- Общий модуль появляется после второго реального потребителя, не раньше.

## 5. Ошибки

- Ожидаемый отказ — именованный DU через `Result`. Строка внутренним error protocol не служит.
- Error DU уровня use case помечай `[<RequireQualifiedAccess>]`: варианты вроде `NotFound` встречаются в нескольких срезах и без квалификации перекрывают друг друга.
- Исключение означает неожиданный технический отказ. При преобразовании сохраняй причину значением: `Storage of exn`, а не `Storage of string` и не `with _ -> None`.
- Недоступность соседа не превращается в пустой успех и не маскируется доменным отказом.
- Слои отображают ошибку исчерпывающим match; HTTP status и wire-код в доменный DU не проникают.

## 6. Порядок компиляции

Порядок `<Compile Include>` в `.fsproj` и есть направление зависимостей: файл видит только объявленное раньше. Обнови его в том же изменении, ставь новый файл в минимально необходимое место, а цикл исправляй границами модулей — не копией типа и не общим `Helpers`.

## 7. Проверь изменение

Прогони настроенные one-shot команды: как минимум `dotnet build` и затронутый test project через `proj-test-fsharp`. Просмотри warnings — exhaustiveness и nullability не закрываются широким catch-all и не подавляются без записанной причины.

Изменение готово, когда публичные сигнатуры показывают допустимые состояния и ошибки, эффекты остались на краю, interop-типы не прошли в домен, а `.fsproj` воспроизводит граф модулей.
