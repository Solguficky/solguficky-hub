# Приёмка сдачи листа

Подагент приёмки сверяет сдачу с шагами 1–11 [контура исполнения](../../../../docs/development/agent-execution-loop.md#шаги-контура) по фактам. Код и дифф он не читает: качество листа проверяют ревью листа и владелец.

Приёмка идёт только по готовому pull request: draft или его отсутствие — остановка листа, а не сдача, и до приёмки она не доходит.

## Вход

- идентификатор листа `PER-X` и номер попытки `k`;
- путь дерева листа из `plan.md` и путь журнала оркестратора `.work/EPIC-<ID>/`;
- отчёт `worker_done` дословно;
- постановку листа из `plan.md` и развилки `D-k`, которые его касаются.

## Чеклист

Каждый пункт — «да», «нет» или «нечем проверить», с источником.

1. **Захват.** Задача в started-статусе (`get_issue`); head pull request — ровно `feature/PER-X` (`gh pr view --json headRefName`).
2. **Дерево.** База pull request — `develop` (`baseRefName`).
3. **Чтение.** В дереве листа есть `.work/PER-X/recon.md` с постановкой, картой файлов и цитатами.
4. **Чекпоинт.** Сработал — в отчёте или в `events.log` и `questions.md` оркестратора есть вопрос и ответ; не сработал — в отчёте строка с выводом `gate-observe plan`; её нет — «нечем проверить», а не «нет».
5. **Реализация.** Не проверяется.
6. **Гейт.** В комментарии Linear на `PER-X` — выбранные рецепты и `EXIT` от `just verify-changed`. «Да» — код 0 либо код 3, при котором названные группы зелёные в прогоне последнего коммита (`gh pr view --json statusCheckRollup`). Любой другой код или красная названная группа — «нет».
7. **Ревью.** Отчёт называет три оси с итогом. Внешнее ревью — его итог либо строка «внешнее ревью не шло» с причиной. Нет ни того, ни другого — «нет»; есть строка с причиной среды — «да» с пометкой: владелец ждёт внешнее ревью на каждом листе, и пометка идёт в сводку.
8. **Коммит.** Заголовки коммитов (`gh pr view --json commits`) — по формату [commit-messages.md](../../../../docs/standards/git/commit-messages.md).
9. **Pull request.** Заголовок — `[PER-X] ` и название задачи из Linear дословно; тело — ровно три раздела из [branching.md](../../../../docs/standards/git/branching.md); pull request не draft.
10. **Отметка.** Комментарий в Linear на `PER-X`: ссылка на pull request, гейт, решения ручного гейта.
11. **Отчёт.** `worker_done` несёт статус, гейт, строки ручного гейта с выводом наблюдателей и отклонения от плана.

## Вердикт

- Все пункты «да», кроме пятого, — `accepted`.
- Есть «нет» — `returned` со списком номеров и тем, чего не хватает; это текст возврата worker'у.
- «Нечем проверить» — не «да»: пункт и причина идут в сводку, решает оркестратор по таблице норматива.

Вердикт пишется в `accept/PER-X-<k>.md`.
