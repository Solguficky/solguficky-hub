Норматив формата: @docs/standards/git/commit-messages.md

Аргумент: `$1` (пусто — только staged; `all` — всё дерево, включая незастейдженное).

Состояние репозитория:

- ветка: !`git branch --show-current`
- статус: !`git status --short`
- staged: !`git diff --cached --stat`
- незастейдженное: !`git diff --stat`
- последние заголовки: !`git log --format=%s -8`

## Что сделать

1. Прочитай норматив выше. Правила про заглавную букву, английский язык, отсутствие тела и запрет идентификатора Linear в заголовке берутся оттуда, а не из памяти.
2. Прочитай сам дифф, а не только `--stat`: `git diff --cached` (или `git diff HEAD`, если аргумент `all`). Заголовок описывает то, что в диффе, а не то, что планировалось.
3. Определи `type` по сути изменения, а не по расширению файлов. Правка `.md`, которая меняет норматив или контракт, — не всегда `docs`.
4. Определи `scope` — сервис или раздел. Если затронуто несколько, scope опусти.
5. Проверь, одно ли это изменение. Если в диффе видно два несвязанных, не склеивай их союзом «и» — предложи разбиение и покажи, какие файлы в какой коммит.

## Что вывести

Сначала само сообщение отдельным блоком, без пояснений внутри него:

```
type(scope): Subject
```

Затем одной строкой — почему выбраны такой type и scope, и что осталось за кадром, если ты что-то в диффе не понял.

Затем готовую команду отдельным `bash`-блоком, чтобы её можно было запустить:

```bash
git commit -m "type(scope): Subject"
```

Сам не коммить. Эта команда только предлагает текст — решение о коммите принимает владелец.
