# Сдать задачу

Норматив — [agent-execution-loop.md](../../../docs/development/agent-execution-loop.md), [branching.md](../../../docs/standards/git/branching.md) и [commit-messages.md](../../../docs/standards/git/commit-messages.md). Не воспроизводи их по памяти: стоп-триггеры, форма PR и формат заголовка коммита читаются оттуда. Здесь только последовательность.

Скилл сдаёт задачу на ревью и на этом останавливается. Статус задачи в Linear он не двигает, pull request не мержит.

## 1. Проверь стоп-триггеры до коммита

Прочитай `git status --short`, `git diff origin/develop...HEAD` и `git diff HEAD` целиком. Второй показывает уже закоммиченное в ветке, третий — то, что ещё не закоммичено; до первого коммита весь срез виден только в третьем. Затем сверь с [нормативом](../../../docs/development/agent-execution-loop.md), сработал ли стоп-триггер.

Этот шаг стоит до проверок намеренно. Триггер «вышел за границы задачи» виден по диффу, а не по цвету гейта: после зелёного `just verify` останавливаться уже поздно.

Триггер сработал — остановись здесь. Покажи `git status --short`, назови триггер и предложи варианты. Дальше по этому скиллу не иди: ни коммита, ни push, ни PR.

## 2. Сверь документацию с кодом

Изменение поведения, команды, контракта или правила без правки документации — не готовый срез, а половина. Проверь адресно:

- новая или изменённая команда — корневой `justfile` и раздел «Команды» в `AGENTS.md`;
- новый каталог верхнего уровня или смена его роли — «Карта репозитория» в `AGENTS.md`;
- новое устойчивое правило — `docs/standards/`, а не текст скилла;
- изменение `contracts/proto/` — [integration.md](../../../docs/architecture/integration.md) и skill `proj-change-contract`.

Документация отстала — допиши её сейчас, тем же изменением. Это правило проекта из `AGENTS.md`, а не пожелание.

## 3. Прогони `just verify`

`just verify` — механический гейт: agent tooling, Identity и тесты. Проверки, которых в нём нет для затронутого среза, добери по `just --list`.

Правил `.skillshare/**` — сначала `skillshare sync -p`, а для команд `skillshare sync extras -p`. Без раскладки таргеты расходятся с источником, и гейт краснеет на `check-agent-tools`.

Правил команду повторно, уже после первой раскладки — `skillshare sync extras -p --force`. Обычный `sync extras` в этом случае считает файл неизменившимся, отчитывается строкой `skipped` и оставляет таргет старым.

Гейт красный — это стоп-триггер. Чистый фикс в границах задачи — почини и прогони заново. Причина не в изменении или фикс тянет правку вне границ — остановись и скажи. Pull request на красном гейте не открывается; подгонять проверку под результат нельзя.

## 4. Прогони ревью

Скилл `proj-review-change`, точка отсчёта — `origin/develop`, источник спецификации — задача `PER-N` в Linear.

Находки разбери по одной: чинишь в границах задачи, либо называешь и оставляешь. Молча проигнорированная находка ревью — та же непроверенная гипотеза, только с подписью «проверено».

## 5. Закоммить

Через skill `proj-write-commit`. Он проверит ветку, одно ли это изменение и формат заголовка.

## 6. Запушь и открой pull request

```
git push -u origin feature/PER-N
gh pr create --base develop --title "[PER-N] Название задачи из Linear" --body-file <файл>
```

Заголовок и три части тела — по [branching.md](../../../docs/standards/git/branching.md): результат проверок, отклонения от утверждённого плана, находки ревью. Пересказ диффа в тело не входит.

Отклонений не было — так и напиши. Пустой раздел честнее удалённого: по нему видно, что вопрос задавался.

Тело передавай файлом (`--body-file`), а не строкой: многострочный `--body` в PowerShell приезжает склеенным.

## 7. Отметься в Linear

`save_comment` на `PER-N`: ссылка на pull request, результат `just verify` и то, что осталось за кадром. Инструмент — [issue-tracker.md](../../../docs/agents/issue-tracker.md).

Статус задачи не трогай. Его переводит Linear по связанному PR либо владелец руками.

## 8. Отчитайся

Ссылка на PR, результат проверок и отклонения от плана явно, отдельной строкой. Отклонение, растворённое в описании сделанного, до владельца не доходит.

Контур на этом закрыт. Следующая задача открывается заново через `/proj-take-task`.
