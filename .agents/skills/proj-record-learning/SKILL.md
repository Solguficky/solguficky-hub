# Записать разбор

Устройство раздела и правила реестра — [docs/learning/README.md](../../../docs/learning/README.md). Стиль — [docs/STYLE.md](../../../docs/STYLE.md). Оттуда же берутся значения статуса усвоения; не воспроизводи их по памяти.

1. Прочитай реестр тем в `docs/learning/README.md`. Разобранное не пересказывай: ссылайся на существующий файл и дописывай только новое.
2. Возьми дифф от точки ветвления: `git diff $(git merge-base develop HEAD)..HEAD`. Разбирается написанное, а не задуманное; догадки о коде, которого в диффе нет, в разбор не попадают.
3. Разложи изменения по темам реестра и покажи раскладку. Тему, которой в реестре нет, заводи только после подтверждения владельца: молча заведённая тема расщепляет реестр на синонимы одной темы.
4. Собери разбор из пяти блоков:
   - **Что появилось и зачем** — только незнакомое читателю. Что уже помечено в реестре как разобранное, объясняется ссылкой.
   - **Почему так, а не иначе** — отвергнутые варианты и цена каждого. Блок без альтернатив превращает разбор в пересказ кода, а учит именно выбор.
   - **Схема** — Mermaid там, где есть путь запроса, порядок сборки или жизненный цикл. Нет механизма — нет схемы.
   - **Первоисточники** — спецификация, релиз-ноты, документация инструмента; каждая ссылка с одной строкой «зачем сюда идти». Первоисточник, а не пересказ в блоге.
   - **Проверь себя** — вопросы, ответ на которые проверяется командой, а не мнением. Ответ пишется рядом.
5. Проверь командой каждое утверждение о поведении инструмента, прежде чем записать его. Проверить не вышло — так и напиши: «проверь сам, когда будет чем», с командой, которой это делается. Разбор читают как источник понимания, и непроверенная точная формулировка в нём хуже честного пробела.
6. Дописывай в файл существующей темы, сохраняя его блоки: тема живёт долго и набирается из многих срезов. Новый файл создавай по имени, согласованному на шаге 3.
7. Обнови реестр: что покрыто и статус усвоения. Статус ставится по факту проверки, а не по ощущению после чтения.
8. Покажи `git status --short` и остановись. Коммит — отдельное решение владельца.

Разбор объясняет, а не нормирует. Правило для code review живёт в `docs/standards/`, устройство компонента — в его брифе, причина решения — в ADR. Разбор на них ссылается.
